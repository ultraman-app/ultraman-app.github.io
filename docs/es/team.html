Trabajar en equipo #

Todo lo que comparte un equipo es un archivo bajo ultraman/, así que tus tests viajan con tu código y un cambio en un test aparece en un pull request como cualquier otro cambio.

Sincronizar #

Si el proyecto está en un repo git con remoto, la barra de arriba dice cuántos archivos faltan sincronizar ("2 cambios sin sincronizar") y ofrece Sincronizar. Guardar (Ctrl+S) solo escribe en tu disco; nada llega al remoto hasta que sincronizás.

Sincronizar toca seis carpetas, y solo esas: ultraman/pipelines/, ultraman/blocks/, ultraman/envs/, ultraman/requests/ (las colecciones), ultraman/load-tests/ y ultraman/files/ (los archivos que mandan las requests). Las commitea (el panel lista los archivos y un mensaje que podés editar), trae los cambios del remoto, los mergea, hace push y recarga. El resto de tu repo, tus otros cambios sin commitear y lo que tengas en staging no se tocan. Usa el git de tu sistema y tus propias credenciales; la app nunca pide una contraseña.

Conflictos #

Si una pipeline cambió en tu disco y en el remoto, un diálogo muestra las dos versiones lado a lado, como pasos o como YAML. Elegí Quedarme con la mía, Usar la del remoto o Guardar la mía como copia. Esc cancela y no cambia nada.

Cuando falla la sincronización #

Sincronizar muestra el motivo y lo que dijo git. Los más comunes:

MensajeQué hacer
The branch … has no remote configuredHacé push una vez: git push -u origin <branch>
You have unpushed commits that touch files outside ultraman/Son tuyos y Ultraman no los pushea: git push, y después sincronizá de nuevo
The remote rejected the pushUna rama protegida o falta de permiso. Tus cambios quedan commiteados en local: pusheálos por una rama y un pull request
Couldn't fetch the remote'sRed o credenciales: probá git fetch en la terminal
Git doesn't know who you aregit config --global user.name "Tu nombre" y git config --global user.email vos@email
There's an unfinished merge or rebaseTerminalo o abortalo en la terminal

Cambió en el disco #

Si hacés git pull en una terminal, o cambiás un YAML con otro editor, la ventana lo nota sola. Si la pipeline que tenés abierta tenía cambios sin guardar, dice "Cambió en disco mientras la editabas" y ofrece Recargar.

Qué queda personal #

Tus secretos, los valores de entorno de esta máquina, el historial, las corridas anteriores y los reportes de carga nunca se sincronizan. Cada persona carga sus propios secretos en su propia bóveda.

Carpetas de confianza #

Una carpeta es de confianza por persona, en esa máquina. En una carpeta en la que no confiaste, Ultraman no manda nada desde la ventana y no corre git, así que no hay sincronización hasta que confíes. Eso te protege cuando abrís un repo que acabás de clonar de otra persona. Confiar es decisión tuya y queda en tu computadora: nunca se guarda en el proyecto.

En pull requests #

Como las pipelines y los tests de carga son YAML, un cambio en un test se ve como un diff legible: qué paso cambió, qué umbral se movió. Una request vinculada en una pipeline dice de dónde vino (from: shop/orders/create).

Qué te mantiene a salvo #

  • Tu equipo: solo esas seis carpetas se commitean y se pushean; los secretos, los valores locales, el historial y los reportes quedan en cada máquina (qué se guarda).
  • Vos: una carpeta en la que no confiaste no manda nada y no corre git (carpetas de confianza).
  • Tu equipo: un cambio en un test es un diff legible, así que un host o un header nuevo no puede colarse sin que se vea.
  • CI: los mismos archivos corren en tu pipeline con sus propios secretos (CI).
