Trabajar en equipo #

Todo lo que comparte un equipo es un archivo dentro de ultraman/. Así, tus pruebas viajan con tu código, y un cambio en una prueba aparece en un pull request como cualquier otro cambio.

Sincronizar #

Si el proyecto está en un repo git con un remoto, la barra superior indica cuántos archivos faltan por sincronizar ("2 cambios sin sincronizar") y ofrece Sincronizar. Guardar (Ctrl+S) solo escribe en tu disco; nada llega al remoto hasta que sincronizas.

La sincronización toca seis carpetas, y solo esas: ultraman/pipelines/, ultraman/blocks/, ultraman/envs/, ultraman/requests/ (las colecciones), ultraman/load-tests/ y ultraman/files/ (los archivos que envían las requests). Hace commit de ellas (el panel muestra los archivos y un mensaje que puedes editar), trae los cambios del remoto, los fusiona, hace push y recarga. El resto de tu repo, tus otros cambios sin commit y lo que tengas en staging quedan intactos. Usa el git de tu sistema y tus propias credenciales; la app nunca te pide una contraseña.

Conflictos #

Si una pipeline cambió tanto en tu disco como en el remoto, un diálogo muestra las dos versiones lado a lado, como pasos o como YAML. Elige Quedarme con la mía, Usar la del remoto o Guardar la mía como copia. Esc cancela sin cambiar nada.

Cuando falla la sincronización #

La sincronización muestra el motivo y lo que respondió git. Los casos más comunes:

MensajeQué hacer
The branch … has no remote configuredHaz push una vez: git push -u origin <branch>
You have unpushed commits that touch files outside ultraman/Son tuyos y Ultraman no los sube: git push y vuelve a sincronizar
The remote rejected the pushUna rama protegida o falta de permisos. Tus cambios siguen en un commit local: súbelos con una rama y un pull request
Couldn't fetch the remote'sRed o credenciales: prueba git fetch en la terminal
Git doesn't know who you aregit config --global user.name "Tu nombre" y git config --global user.email tu@email
There's an unfinished merge or rebaseTermínalo o cancélalo en la terminal

Cambió en el disco #

Si haces git pull en una terminal, o cambias un YAML con otro editor, la ventana lo detecta por sí sola. Si la pipeline que tienes abierta tenía cambios sin guardar, muestra "Cambió en disco mientras la editabas." y ofrece Recargar.

Qué es personal #

Tus secretos, los valores de entorno de esta máquina, el historial, las ejecuciones anteriores y los reportes de carga nunca se sincronizan. Cada persona guarda sus propios secretos en su propia bóveda.

Carpetas de confianza #

La confianza en una carpeta es de cada persona, en su máquina. En una carpeta en la que no has confiado, Ultraman no envía nada desde la ventana ni ejecuta git, así que no hay sincronización hasta que confíes en ella. Eso te protege cuando abres un repo que acabas de clonar de otra persona. Confiar es decisión tuya y queda en tu computadora: nunca se guarda en el proyecto.

En los pull requests #

Como las pipelines y las pruebas de carga son YAML, un cambio en una prueba se ve como un diff legible: qué paso cambió, qué umbral se movió. Una request vinculada en una pipeline indica de dónde viene (from: shop/orders/create).

Qué te mantiene a salvo #

  • Tu equipo: solo esas seis carpetas se incluyen en el commit y el push; los secretos, los valores locales, el historial y los reportes se quedan en cada máquina (qué se guarda).
  • Tú: una carpeta en la que no has confiado no envía nada ni ejecuta git (carpetas de confianza).
  • Tu equipo: un cambio en una prueba es un diff legible, así que un host o un header nuevo no puede colarse sin que nadie lo vea.
  • CI: los mismos archivos se ejecutan en tu pipeline de CI con sus propios secretos (CI).
