Lo que te da Ultraman #

Ultraman prueba APIs HTTP, WebSocket y SSE incluidos: una sola app en tu computadora para requests sueltas, pruebas de varios pasos, carga y CI, todo guardado como archivos simples en tu propio repo de git. Ultraman nunca envía nada de forma insegura sin tu consentimiento explícito: un secreto va solo a un host que aprobaste, y una carpeta en la que no confiaste no envía nada.

Cada parte de abajo dice qué hace por vos y dónde leer más. Si preferís arrancar según tu rol, andá a Por dónde empezar.

Pipelines que se ven #

Una pipeline es una prueba escrita como una lista de pasos: iniciar sesión, tomar el token de la respuesta, crear un pedido, chequear que aparece. Es una prueba que se lee como una oración: cada paso es una fila ("token ← $login $.token"), y la misma pipeline se ve como diagrama, con una flecha desde la request que produce un valor hasta la que lo usa. Se guarda como YAML en tu repo, así que un cambio en una prueba se revisa en un pull request como cualquier otro código. → Pipelines

Requests como en Postman, con memoria #

Para cuando solo querés probar una llamada: colecciones, carpetas, pestañas, Enviar. Cada request guarda sus propios checks, y cada envío queda en el historial con su tiempo, así podés ver qué respondió un endpoint ayer. Cuando una respuesta cambia de forma respecto de la anterior, Ultraman te avisa. Los streams WebSocket y SSE se abren en una pestaña propia. → Requests

Carga de verdad #

La pipeline que ya tenés, corrida por muchos usuarios virtuales o a una tasa de llegada fija: sabés cómo se comporta tu API bajo carga sin escribir una segunda prueba. Rampas, mesetas, tiempo de pensar, datos y cookies por usuario, varios escenarios mezclados por peso, hasta 8 hilos en una máquina. El reporte da un veredicto en palabras (aguantó, hizo cola, rechazó requests…) y avisa cuando el límite fue tu propia computadora y no la API. → Carga

Traé lo que ya tenés #

No empezás de cero: colecciones y entornos de Postman, documentos OpenAPI, planes de JMeter, scripts de Artillery y tráfico grabado en tu navegador se vuelven colecciones, pipelines, entornos y tests de carga. Lo que no se puede traducir queda listado, no se pierde. Una importación lee solo el archivo que elegís y no envía nada. → Importar

Tus secretos van solo adonde dijiste #

Ultraman nunca envía nada de forma insegura sin tu consentimiento explícito. Un secreto, escrito {{secrets.token}}, vive en una bóveda cifrada en tu computadora, nunca en el repo. La primera vez que una request lo enviaría a un servidor que no aprobaste para ese secreto, Ultraman pregunta; lo mismo con un archivo de fuera de la carpeta ultraman/files/ del proyecto. Donde se vería el valor de un secreto (una respuesta, el historial, un reporte de ejecución, una exportación), ves [secret:token]. Una carpeta en la que todavía no confiás se abre en modo restringido: no envía nada y no ejecuta git. Eso es lo que te deja abrir una pipeline que escribió un colega, o una de internet, sin que mande tu token a otro lado en silencio. Lo que esto no puede cubrir se dice sin vueltas en los límites. → Seguridad y consentimiento, Entornos y secretos

Un equipo que comparte por git #

Tu equipo comparte pruebas como comparte código, sin cuenta ni servidor de por medio: pipelines, colecciones, entornos, tests de carga y los archivos que mandan las requests son todos archivos dentro de ultraman/. Sincronizar hace commit y push solo de eso, y muestra los conflictos lado a lado. Los secretos, los valores de esta máquina y tu historial quedan en tu computadora. → Trabajo en equipo

Las mismas pruebas en CI #

Las pruebas que corrés en la ventana pueden frenar tu build. ultraman run corre pipelines, una colección o un test de carga desde una terminal, escribe un reporte JUnit y sale con error cuando falla un check o un umbral. En GitHub Actions, ultraman-app/run-action lo instala y lo corre; vos decís a qué servidor puede ir cada secreto. → CI, La terminal

Tu agente lo puede manejar #

Un agente de IA que hable MCP (Claude Code, por ejemplo) puede crear requests, escribir pipelines, correrlas, iniciar una carga y leer los reportes, mientras vos seguís al mando: cada llamada muestra una tarjeta en la ventana y no pasa nada hasta que la aprobás (las llamadas de solo lectura se pueden dejar pasar el resto de una sesión). El agente puede usar tus secretos por su nombre, pero nunca ve sus valores. → Agentes (MCP)

Una API de mentira con lo que ya enviaste #

Cuando la API real está caída, lenta o todavía no existe, el servidor mock responde con las respuestas que ya grabaste, así un front end o una prueba pueden seguir trabajando. Responde solo en tu computadora, salvo que lo inicies desde la terminal y elijas otra cosa. → Servidor mock
