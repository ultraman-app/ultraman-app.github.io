Servidor mock #

El servidor mock contesta las requests a tu API con respuestas que ya grabaste, así un front end (o un test) puede trabajar mientras la API real está caída, lenta o todavía no existe. Corre en tu computadora y nadie más puede alcanzarlo a menos que vos lo decidas.

De dónde saca las respuestas #

Del Historial: cada request que mandaste es una grabación. En el Historial, abrí Servidor mock: lista las rutas que puede contestar (método y path, con parámetros de path) para el entorno elegido.

Iniciarlo #

Elegí un puerto e Iniciar (4300 por defecto). Solo contesta en esta máquina, y solo arranca en una carpeta de confianza (la terminal pregunta).

  • Demora grabada contesta tan lento como lo hizo la API real.
  • Reenviar el resto a manda a un host real lo que no tiene grabado.
  • Una ruta con varias grabaciones contesta con la más nueva; fijá una en particular, o elegí En orden para recorrerlas una por una (Reiniciar secuencias empieza de nuevo).

Qué grabación contesta #

Una request se empareja en este orden, y gana la primera coincidencia:

  1. el mismo método, path y query (el orden de los parámetros de la query no importa);
  2. el mismo método y path, con cualquier query;
  3. el template de path de la request: /users/:userId/orders contesta /users/u_bob/orders con la grabación de u_ana.

Sin coincidencia, el mock contesta 404 con las rutas conocidas. Si una ruta tiene varias grabaciones, contesta la más nueva, salvo que fijes una o elijas En orden. Solo se sirven las grabaciones del entorno elegido, y un envío nuevo se toma sin reiniciar. Cada respuesta lleva headers x-ultraman-mock que dicen qué grabación fue, y una respuesta demasiado grande o binaria se corta o queda vacía, con un header que lo dice. Las cookies y los tokens que puso la API real se sirven tal como se grabaron.

Desde la terminal #

ultraman mock --env local --port 4300 inicia el mismo servidor sin la ventana; --proxy <url> reenvía el resto.

Para que otras computadoras de tu red lo alcancen, la terminal tiene --expose. No está en la ventana y un agente no puede activarlo. Ultraman avisa que cualquiera en tu red puede leer las respuestas, que pueden tener datos reales, y espera un Enter (o --yes). Con --proxy también, avisa que cualquiera en tu red, y cualquier página web abierta ahí, podría llamar a esa API a través de esta máquina con el acceso de esta máquina. Lo seguro es dejar --expose afuera.

Qué te mantiene a salvo #

  • Vos: el mock escucha solo en 127.0.0.1 y contesta solo requests que nombran esta máquina. Una página web de otro sitio recibe un rechazo, así que un sitio que visitás no puede leer tus grabaciones ni alcanzar una API a través de --proxy.
  • Vos: --proxy reenvía solo a la dirección que das, y no agrega credenciales propias.
  • Tu equipo: las grabaciones salen de tu historial personal, que nunca se sincroniza. Los secretos que haya ahí ya están ocultos como [secret:x]. Ver dónde se guarda cada cosa y el servidor local.
  • Vos: --expose es una decisión deliberada y advertida en la terminal. Ver los límites.
