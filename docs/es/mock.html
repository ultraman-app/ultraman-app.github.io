Servidor mock #

El servidor mock responde las requests a tu API con respuestas que ya grabaste. Así, un front end (o un test) puede seguir trabajando aunque la API real esté caída, vaya lenta o todavía no exista. Se ejecuta en tu computadora y nadie más puede acceder a él, salvo que tú lo decidas.

De dónde saca las respuestas #

Del Historial: cada request que enviaste es una grabación. En el Historial, abre Servidor mock: verás las rutas que puede responder (método y path, con parámetros de path) para el entorno elegido.

Iniciarlo #

Elige un puerto y pulsa Iniciar (por defecto, 4300). Solo responde en esta máquina y solo se inicia en una carpeta de confianza (la terminal te lo pregunta).

  • Demora grabada responde con la misma lentitud que tuvo la API real.
  • Reenviar el resto a envía a un host real todo lo que no tiene grabado.
  • Si una ruta tiene varias grabaciones, responde con la más reciente. Puedes fijar una en concreto, o elegir En orden para recorrerlas una por una (Reiniciar secuencias vuelve a empezar).

Qué grabación responde #

Las requests se comparan en este orden, y gana la primera que coincida:

  1. el mismo método, path y query (el orden de los parámetros de la query da igual);
  2. el mismo método y path, con cualquier query;
  3. el template de path de la request: /users/:userId/orders responde a /users/u_bob/orders con la grabación de u_ana.

Si nada coincide, el mock responde 404 con la lista de rutas conocidas. Si una ruta tiene varias grabaciones, responde la más reciente, a menos que fijes una o elijas En orden. Solo se sirven las grabaciones del entorno elegido, y un envío nuevo se incorpora sin reiniciar. Cada respuesta lleva headers x-ultraman-mock que indican de qué grabación salió. Una respuesta demasiado grande o binaria se recorta o queda vacía, con un header que lo indica. Las cookies y los tokens que estableció la API real se sirven tal como se grabaron.

Desde la terminal #

ultraman mock --env local --port 4300 inicia el mismo servidor sin la ventana; --proxy <url> reenvía el resto.

Para que otras computadoras de tu red puedan acceder, la terminal ofrece --expose. No está en la ventana y un agente no puede activarlo. Ultraman advierte que cualquiera en tu red podrá leer las respuestas, que pueden contener datos reales, y espera a que pulses Enter (o a --yes). Si además usas --proxy, advierte que cualquiera en tu red, y cualquier página web abierta en ella, podría llamar a esa API a través de esta máquina y con los accesos de esta máquina. Lo seguro es no usar --expose.

Qué te mantiene a salvo #

  • Tú: el mock escucha solo en 127.0.0.1 y solo responde a requests dirigidas a esta máquina. Una página web de otro sitio recibe un rechazo, así que un sitio que visites no puede leer tus grabaciones ni llegar a una API a través de --proxy.
  • Tú: --proxy reenvía solo a la dirección que indicas y no agrega credenciales propias.
  • Tu equipo: las grabaciones salen de tu historial personal, que nunca se sincroniza. Los secretos que contenga ya aparecen ocultos como [secret:x]. Consulta dónde se guarda cada cosa y el servidor local.
  • Tú: --expose es una decisión deliberada, con advertencia en la terminal. Consulta los límites.
