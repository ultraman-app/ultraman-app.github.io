Preguntas #

Respuestas cortas a lo que los equipos preguntan antes de adoptar Ultraman, incluidos los "no" honestos. Cada respuesta enlaza a la página que profundiza.

Confianza y seguridad #

¿Podría mandar mi token a un lugar equivocado? #

Un secreto va solo a un origen (esquema, host y puerto) al que dijiste que sí; la primera vez que iría a un lugar nuevo, Ultraman pregunta, y en una terminal también pregunta. Cuando una redirección lleva a otro origen, las credenciales se descartan. En una carpeta en la que no confiaste, la ventana no manda nada y no corre git. Ver Seguridad y consentimiento.

¿Un agente de IA puede ver mis secretos? #

No. Un agente conectado por MCP puede usar {{secrets.x}}, pero el valor nunca le llega, y cada llamada muestra una tarjeta en la ventana que aprobás o rechazás. No puede abrir la bóveda, decir que sí a un host nuevo, confiar en una carpeta, sincronizar con git ni borrar nada. Un token que un paso extrae de una respuesta es un dato, no un secreto: la tarjeta que entrega un resultado resalta los tokens antes de que lo apruebes. Ver Agentes.

¿Manda algo sobre mí? #

Sin telemetría y sin cuenta. Mientras la ventana está abierta, Ultraman le pregunta a GitHub como mucho una vez por día si existe una versión más nueva, y no manda nada sobre vos ni sobre tus proyectos; ULTRAMAN_NO_UPDATE_CHECK=1 lo apaga. No se descarga nada hasta que elegís Actualizar y reiniciar. Ver Qué sale de tu máquina.

¿En qué sistemas corre? #

Windows (x64), macOS (Apple silicon e Intel) y Linux (x64, como AppImage). Los instaladores no están firmados por Microsoft ni por Apple, así que el primer arranque muestra una advertencia; las actualizaciones y los checksums de los scripts de instalación sí están firmados. Ver La advertencia del primer arranque.

¿Cómo comparto secretos con mi equipo? #

No los compartís. Cada persona carga sus propios valores en su propia bóveda, con los nombres que usa el entorno (staging.token); CI recibe los suyos por ULTRAMAN_SECRET_*. El repo lleva solo {{secrets.x}}. Ver Secretos.

Qué hace y qué no hace #

¿Puedo escribir scripts? #

No, a propósito: lo que hace un paso siempre está a la vista, y quien revisa lo lee en un diff sin correr nada. En su lugar hay asserts, extracts (por path JSON, header o regex), pasos if y repeat, bloques reutilizables, y funciones dentro de {{ }} como random.uuid, now.iso, base64(x) y hmac.sha256(secrets.key, body). Cuando importás, los test scripts comunes de Postman pasan a ser checks; los demás scripts se listan para vos, nunca se corren. Ver Ayudas.

¿Qué protocolos habla? #

HTTP y HTTPS, WebSocket y Server-Sent Events (SSE). Los streams funcionan como requests en el área Requests, como pasos de pipeline y bajo carga. No están soportados: Socket.IO, WebSockets comprimidos, reconexiones automáticas (conectá de nuevo, o escribí el reintento como pasos) ni un mock para streams. Ver Streams.

¿Hace gRPC? #

No. Ultraman prueba APIs HTTP, incluidos los streams WebSocket y SSE; para gRPC, elegí una herramienta que lo soporte (ver Cuándo elegir otra cosa).

¿Hace GraphQL? #

No hay soporte dedicado para GraphQL: ni schema, ni editor de queries. Una query GraphQL es un POST HTTP con un body JSON, así que la podés mandar como cualquier request y chequear el resultado. Un servidor GraphQL suele contestar 200 incluso cuando la query falló, así que agregá un assert de que $.errors no exista. Ver Checks.

¿Qué tipos de autenticación soporta? #

Bearer token, basic auth y API key (en un header o en la query string), definidos en una request, una colección o una pipeline. ca confía en la autoridad certificadora de tu propio servidor. No hay certificados de cliente (mTLS), flujos OAuth2, AWS SigV4 ni NTLM. Para una API que reparte tokens, un paso de login, un extract del token y una auth bearer que lo use cubren el caso habitual. Ver Pipelines.

¿Puedo traer mi trabajo existente? #

Sí: colecciones y entornos de Postman, documentos OpenAPI 3, planes .jmx de JMeter, scripts de Artillery, y tráfico grabado en tu navegador como archivo HAR. Los secretos de un entorno de Postman van a la bóveda. Lo que no se puede traducir se lista, no se pierde, y una importación nunca manda una request ni corre un script. Ver Importar.

¿Necesita Node, Java o algo instalado? #

No. El instalador trae todo, Node incluido, a tu carpeta de usuario, sin permisos de administrador. Ver Instalar.

¿Lo puedo usar sin la app de escritorio? #

Sí: instalá solo el comando (--cli) para una máquina de build o un servidor. La ventana es donde respondés las preguntas de consentimiento y aprobás las tarjetas de agentes; el comando pregunta en la terminal en su lugar. Ver La terminal.

Equipos y CI #

¿Quién puede ver y cambiar nuestros tests? #

Quien pueda leer o escribir tu repo git: Ultraman no tiene cuentas, roles ni workspaces propios. Los cambios en los tests llegan al equipo con Sincronizar y se revisan como pull requests. Los secretos nunca se sincronizan: cada persona guarda los suyos en su propia bóveda. Ver Trabajar en equipo.

¿Qué pasa cuando dos cambiamos la misma pipeline? #

Sincronizar muestra las dos versiones lado a lado, como pasos o como YAML, y elegís Quedarme con la mía, Usar la del remoto o Guardar la mía como copia. Esc cancela y no cambia nada. Ver Conflictos.

¿Funciona en CI? #

Sí. ultraman run corre pipelines, colecciones o tests de carga, escribe un reporte JUnit y sale con 0 (pasó), 1 (falló un check o un umbral) o 2 (no pudo correr). En GitHub, la action ultraman-app/run-action@v1 lo instala y lo corre; en otros sistemas, instalá solo la CLI. Un runner no tiene bóveda: los secretos vienen de variables de entorno ULTRAMAN_SECRET_<NAME>. Ver CI.

Carga #

¿Un test de carga puede correr en varias máquinas? #

No. Una carga corre en una computadora, en un hilo por defecto y hasta 8 con --workers. Si necesitás carga desde muchas máquinas o desde la nube, elegí una herramienta pensada para eso (ver Cuándo elegir otra cosa).

¿Cuánta carga puede generar? #

Tanta como pueda mandar tu computadora: depende de la máquina, de la red y de lo pesada que sea cada request. La franja Esta computadora vigila tu máquina durante la corrida, y cuando ella fue el cuello de botella el veredicto dice limited en vez de culpar a la API. Ver Más de un hilo.
