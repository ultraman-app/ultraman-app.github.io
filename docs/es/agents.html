Agentes (MCP) #

Un agente de IA (Claude Code o cualquier otro cliente MCP) puede usar Ultraman a través de ultraman mcp. Puede hacer lo mismo que tú en la ventana: leer y escribir requests, pipelines y pruebas de carga, enviarlas y ejecutarlas, importar, iniciar el servidor mock, leer reportes y compararlos. Tú apruebas cada llamada.

Conectarlo #

ultraman mcp es un servidor MCP sobre stdio. En Claude Code:

claude mcp add ultraman -- ultraman mcp --project <your project folder>

Cualquier otro cliente MCP acepta lo mismo en su propia configuración: un servidor stdio cuyo comando es ultraman y cuyos argumentos son mcp --project <la carpeta de tu proyecto>. Sin --project, el proyecto es la carpeta desde la que lo inicias (o la más cercana por encima de ella que tenga ultraman/).

Tienen que cumplirse dos condiciones; si no, cada herramienta responde "open Ultraman on this project to approve the agent's requests":

  • la ventana de Ultraman está abierta en ese proyecto, porque ahí es donde apruebas;
  • la carpeta es de confianza en la ventana (carpetas de confianza).

Tú apruebas cada llamada #

Cada cosa que pide el agente aparece como una tarjeta abajo a la derecha: quién lo pide, qué pide y el detalle (si es un cambio, el diff). Pulsa Aprobar o Rechazar (con un motivo que el agente lee). Las peticiones de solo lectura se pueden aprobar "siempre"; eso dura solo mientras dure la sesión actual del agente, y solo mientras Ultraman siga abierto.

Lo que se ejecuta (una pipeline, una request, una carga) tiene dos tarjetas: una para iniciarlo y otra para entregarle el resultado al agente. La tarjeta de entrega avisa cuando el resultado contiene tokens, cookies o headers de autenticación. Si rechazas una entrega, el rechazo es definitivo.

Una llamada dura como máximo unos 50 segundos, porque la mayoría de los clientes cortan una llamada a una herramienta a los 60: una ejecución larga sigue en marcha y el agente pide su resultado más tarde. Mientras una tarjeta espera tu respuesta, el agente recibe un aviso de progreso cada 5 segundos. Cada petición queda registrada en ultraman/mcp/, que git ignora.

Un stream WebSocket o SSE se envía de una sola vez (send_stream, o una request de stream guardada): se abre, envía los mensajes de la tarjeta, escucha durante el tiempo que indica la tarjeta (30 segundos como máximo) y se cierra; la entrega incluye el handshake y los mensajes en ambos sentidos (los primeros 50, cada uno recortado a 4 KB). Con graphql se trata, en cambio, de una suscripción GraphQL: la tarjeta muestra la query, la operación y el payload de connection_init tal como están escritos (un secreto aparece como su referencia), y solo sale una suscripción; la entrega incluye los payloads de los eventos. El agente no tiene sesiones en vivo: si necesitas una que siga abierta, usa la ventana.

Qué puede hacer #

Las herramientas se agrupan en las mismas áreas que la ventana:

  • Pipelines y bloques: listarlos, leerlos, guardarlos y ejecutarlos; leer ejecuciones anteriores; convertir un archivo HAR o entradas del historial en una propuesta de pipeline.
  • Requests: listar, leer y guardar colecciones y requests, moverlas y organizarlas, agregar una a una pipeline, enviar una request guardada con sus checks, ejecutar una colección, enviar una request puntual (también GraphQL: su resultado enumera los errores de la respuesta), leer el schema de una request GraphQL (get_graphql_schema, un envío como cualquier otro), leer el historial.
  • Streams: envíos WebSocket y SSE de una sola vez.
  • Carga: listar, leer y guardar pruebas de carga, ejecutar una, leer reportes, comparar dos, ver la tendencia, exportar.
  • Proyecto: listar y guardar entornos, listar secretos (solo los nombres), importar un archivo de Postman, OpenAPI, JMeter o Artillery, actualizar una colección a partir de una spec OpenAPI más reciente (update_collection_from_openapi), leer la referencia del formato YAML.
  • Servidor mock: estado, iniciar, detener, reiniciar, fijar una grabación.

Una escritura muestra su diff (o el archivo nuevo completo) en la tarjeta. Un guardado que activa http sin cifrar o una CA propia se marca en rojo.

Qué no puede hacer #

Por diseño, el agente no puede ver ni definir el valor de un secreto, desbloquear la bóveda, dar un sí a un consentimiento, confiar en una carpeta, sincronizar con git ni borrar nada. Todo eso queda en tus manos, en la ventana. Puede usar {{secrets.x}}; el valor nunca le llega, y los resultados se ocultan antes de entregárselos.

Hay algo que no es un secreto: un token que un paso extrae de una respuesta (por ejemplo, el access_token de un login) es un dato más, así que sí le llega al agente. Por eso la tarjeta de entrega resalta los tokens, las cookies y los headers de autenticación antes de que apruebes.

Hacerle preguntas #

El agente lee este mismo manual (get_manual) y la referencia del formato YAML (get_reference), así que puedes preguntarle "¿cómo ejecuto esto con 50 usuarios?" o "crea una pipeline que haga login y cree un pedido", y te propondrá el cambio para que lo apruebes. Lo que dice un resultado se le entrega como datos para leer, no como instrucciones para seguir.

La aprobación protege lo que pasa por el canal MCP. Un agente con acceso a una shell (Claude Code lo tiene) también puede leer los archivos de tu proyecto o ejecutar ultraman run por su cuenta, y eso queda fuera del alcance de Ultraman. Considera las tarjetas un consentimiento, no un sandbox, y dale a un agente solo el acceso que le darías a un colega.

Qué te mantiene a salvo #

  • Tú: nada de lo que pide el agente ocurre hasta que apruebas su tarjeta, y una entrega rechazada sigue rechazada (agentes).
  • Tú: el agente nunca ve el valor de un secreto y no puede desbloquear la bóveda, dar un consentimiento, confiar en una carpeta, sincronizar ni borrar (ocultamiento).
  • Tú: el agente no puede aprobarse a sí mismo: toda decisión necesita la ventana (servidor local).
  • Tu equipo: las peticiones del agente quedan registradas en ultraman/mcp/, solo en tu máquina.
  • Límite: un agente con su propia shell queda fuera del alcance de las tarjetas (límites).
