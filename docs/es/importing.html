Importar #

Los botones al lado de Nueva colección (área Requests) traen lo que ya tenés: una exportación de Postman, una spec OpenAPI, un plan de JMeter, un script de Artillery o una grabación del navegador, así no arrancás de cero. No se sobrescribe nada del proyecto: un nombre que ya existe recibe -2. Al final, un resumen dice qué entró, qué se adaptó, qué necesita una mano y qué archivos se salteó.

Desde Postman #

El botón de importar toma colecciones (v2.0, v2.1), entornos y globales exportados de Postman. Carpetas, requests, bodies, auth (bearer, basic, API key), variables y descripciones entran como estaban. Los secretos de los entornos van a la bóveda, nunca a un archivo. Los scripts de test comunes (status, equals, includes, tiempo de respuesta, pm.environment.set) pasan a ser checks; el resto queda en las Notas de la request.

Desde OpenAPI #

API toma un documento OpenAPI 3 (JSON o YAML) y arma una colección: una request por operación, con bodies de ejemplo y checks de contrato (status y forma de la respuesta).

Desde JMeter #

JMX toma un plan .jmx: una pipeline por Thread Group, un bloque de preparación a partir de un Once Only Controller, un entorno a partir de las User Defined Variables, y un test de carga con un escenario por grupo. Lo que no se traduce (scripts, algunos controllers) se lista como "needs a hand" con su texto.

Desde Artillery #

ART toma un script de Artillery (.yml o .json): pipelines, bloques before/after, entornos y un test de carga con sus fases como etapas y pesos. Los processors y hooks se listan, no se corren.

Desde tráfico grabado #

Desde un archivo HAR… (área Pipelines) convierte una grabación del navegador en una pipeline. En Chrome o Firefox: DevTools › Network › clic derecho › Save all as HAR. Ultraman se queda con las llamadas a la API, encuentra los valores que una respuesta le da a la siguiente (un id, un token) y los convierte en extracts visibles, así la pipeline funciona de nuevo en vez de repetir valores viejos.

Una grabación puede contener contraseñas y tokens: Ultraman reemplaza por {{secrets.x}} los que conoce de tu bóveda, pero leé la propuesta antes de guardar.

Lo que una importación nunca hace #

Una importación solo lee el archivo que elegiste y escribe archivos en tu proyecto. Nunca manda una request, nunca lee ningún otro archivo de tu disco, nunca baja una dirección nombrada dentro del archivo (un $ref de OpenAPI a una URL se anota, no se sigue), nunca expande entidades XML en un .jmx y nunca corre un script: los test scripts de Postman, los processors de JMeter y los hooks de Artillery se listan en "needs a hand" con su texto, y solo los casos comunes y simples pasan a ser checks.

Un archivo de otra persona puede contener cualquier cosa, pero importarlo es tan seguro como abrirlo como texto. Revisá lo que entró antes de correrlo: la primera corrida es la que manda.

Qué te mantiene a salvo #

  • Vos: importar no manda nada ni corre nada; la primera request sale solo cuando la mandás o la corrés, con el sí habitual para cualquier secreto. Ver consentimiento.
  • Vos y tu equipo: los valores secretos de un entorno de Postman van a la bóveda, nunca a un archivo del proyecto. En un HAR, los valores que coinciden con tu bóveda pasan a ser {{secrets.x}}; leé la propuesta antes de guardar, ya que una grabación puede tener contraseñas que nunca guardaste. Ver la bóveda.
  • Vos: una pipeline que vino de afuera igual no puede leer un secreto en un check, ni mandar sin que lo pidas un archivo de fuera de ultraman/files/. Ver archivos.
