La terminal #

El comando ultraman ejecuta tus pipelines y pruebas de carga desde una terminal, sirve el proyecto a otras herramientas y guarda secretos en la bóveda. Ejecútalo desde la carpeta del proyecto (o desde cualquier carpeta dentro de ella). Para usarlo en una máquina de build, consulta CI.

Los comandos #

ComandoQué hace
ultraman run <pipeline>Ejecuta una pipeline; la busca primero por nombre y luego por id.
ultraman run --all, --tag X, --collection IDEjecuta varias pipelines a la vez.
ultraman run --load <test>Lanza una prueba de carga; ultraman run <pipeline> --load usa la prueba por defecto de esa pipeline.
ultraman serve [--port 4100]Inicia el servidor local del proyecto (con el que se comunican la ventana y los demás comandos).
ultraman secret set <name>, list, rm <name>, passwordAdministra la bóveda.
ultraman mock [--port 4300]Sirve tu historial grabado como una API mock. Consulta Servidor mock.
ultraman mcp [--project <folder>]El puente al que se conecta un agente de IA. Consulta Agentes.
ultraman sampleDeja el proyecto de ejemplo como nuevo en la carpeta propia de Ultraman y muestra su ruta. Consulta el proyecto de ejemplo.
ultraman --versionMuestra la versión.

Un comando sin argumentos, o uno desconocido, muestra cómo se usa y termina con 2.

Ejecutar pipelines #

ultraman run "create order" --env local --input user=ana
ultraman run --all --env ci --yes
ultraman run --tag smoke --env ci --parallel 4
ultraman run --collection shop --env staging

Indica exactamente una de estas opciones: una pipeline, --all, --tag o --collection; cualquier otra combinación termina con 2. Antes de que salga la primera request, se verifica todo en todas las pipelines elegidas.

FlagQué hace
--allTodas las pipelines del proyecto.
--tag XLas pipelines con esa etiqueta. Si lo repites, una pipeline necesita tener todas las etiquetas indicadas.
--collection IDEjecuta una colección; shop/orders ejecuta solo esa carpeta.
--env XEl entorno. Si el proyecto tiene un solo entorno, se usa ese; si tiene varios, debes pasar --env.
--input k=vUn valor para un input; repítelo para agregar más. Un valor que empieza con [ o { se lee como JSON si es válido; cualquier otro queda como texto (id=00123 sigue siendo 00123). Los nombres env.* y secrets.* están reservados.
--parallel NEjecuta hasta N pipelines al mismo tiempo (de 1 a 16). Cada una se muestra completa al terminar.
--bailDeja de iniciar pipelines nuevas después de la primera que falle. Las que están en marcha terminan; las demás aparecen como omitidas.
--watchVuelve a ejecutar cada vez que cambia un archivo dentro de ultraman/.
--every DVuelve a ejecutar cada cierto tiempo: 30s, 5m, 1h o un número de segundos sin unidad, con un mínimo de 5 segundos. Cuenta desde el final de la ejecución anterior y se puede combinar con --watch.
--no-notifyCon --watch o --every, desactiva la notificación de escritorio cuando una ejecución falla y cuando vuelve a pasar.
--jsonUn evento JSON por línea en la salida estándar, para otras herramientas. Sin colores.
--junit FILEEscribe un reporte JUnit XML. Consulta JUnit.
--contract Mstrict, warn u off: sustituye el modo de contrato de cada colección, para que CI falle con lo que la spec no documenta. Consulta el contrato.
--localEjecuta en este proceso aunque la ventana tenga el proyecto abierto. Consulta Un solo motor.
--yesResponde que sí a todas las preguntas. Antes, lee Consentimiento en la terminal.

Cada ejecución se guarda en ultraman/runs/. Los colores solo aparecen en una terminal; NO_COLOR los desactiva. Ctrl+C cancela el paso en curso, guarda la ejecución y termina con 1.

Códigos de salida: 0 todo pasó; 1 falló un paso (o presionaste Ctrl+C); 2 no llegó a ejecutarse: un flag incorrecto, falta una pipeline, un input, un entorno o un secreto, una pipeline no es válida, o no se envió nada porque nadie dio un sí.

Consentimiento en la terminal #

Ultraman pregunta antes de enviar algo que no hayas aprobado. En una terminal pregunta cuando:

  • todavía no confías en la carpeta;
  • un secreto iría a un origen al que nunca ha ido;
  • se enviaría un archivo que está fuera de ultraman/files/.

La pregunta detalla qué iría a dónde, y respondes y (esta vez), a (siempre, para este proyecto) o N (la opción por defecto: no se envía nada). "Siempre" se guarda en ~/.ultraman/trust.json, en tu máquina, nunca en el proyecto, así que el checkout de un compañero no puede traerlo. El modelo completo está en Seguridad y consentimiento.

Sin terminal y sin --yes no hay a quién preguntar: Ultraman muestra lo que enviaría y termina con 2, sin haber enviado nada.

`--yes` se salta todas las preguntas. Todo lo que indiquen las pipelines y los entornos va adonde indiquen, tus secretos incluidos, y también un valor tomado de una respuesta que contiene un secreto. Úsalo solo donde únicamente tu equipo pueda cambiar esos archivos; nunca con código de forks o de personas que no conoces. En CI se explica la forma más segura para GitHub Actions.

Ejecutar una prueba de carga #

ultraman run --load checkout-peak --env staging --junit load.xml --html report.html --baseline last

La prueba es ultraman/load-tests/<nombre>.yaml, indicada por nombre o por id. Además de --env, --input, --junit, --json, --local y --yes (que funcionan igual que arriba), una carga acepta:

FlagQué hace
--target URLEnvía todo a otro origen en esta ejecución (https://staging.example.com, con un path base opcional, sin usuario, contraseña, ? ni #).
--overrides JSONReemplaza claves de primer nivel de la prueba en esta ejecución, escritas igual que en el YAML.
--workers NGenera la carga con N hilos (de 1 a 8). Por defecto, uno, o el valor de ULTRAMAN_LOAD_WORKERS.
--output FILEEscribe el reporte final en JSON.
--html FILEEscribe el reporte como una sola página autocontenida.
--csv DIREscribe las series y los pasos como archivos CSV en esa carpeta.
--baseline last o un archivoMuestra cómo se compara esta ejecución con un reporte anterior: el último guardado para esta prueba, o un archivo JSON.

--all, --tag, --collection, --bail, --parallel, --watch y --every no se aplican a una carga.

Códigos de salida: 0 se cumplieron todos los umbrales y el veredicto es aguanta, encola o limitado; 1 falló un umbral, la API rechazó o se rompió, salieron muy pocas requests, o la carga se detuvo (con Ctrl+C o por los frenos del propio generador); 2 no se envió nada. Los umbrales y los veredictos se explican en Carga; para usarlos como compuertas en una pipeline, consulta CI.

JUnit para CI #

--junit FILE escribe un reporte JUnit XML al terminar las ejecuciones, también después de un Ctrl+C con lo que llegó a ejecutarse: un test suite por pipeline y un test case por paso de primer nivel, con lo que se envió y se recibió en los que fallaron. Los secretos aparecen ocultos, como en todas partes. Las carpetas que falten se crean.

ultraman run --all --env ci --yes --junit reports/ultraman.xml

Secretos #

En tu máquina, ultraman secret set api-key guarda un secreto en la bóveda: te pide la contraseña maestra y el valor, sin mostrar ninguno de los dos en pantalla. Si el valor llega por un pipe (echo "$VALUE" | ultraman secret set api-key), se lee de la entrada estándar; la contraseña maestra sigue necesitando una terminal. Los nombres usan letras, dígitos, _, . y -. secret list muestra los nombres, secret rm <name> elimina uno (termina con 1 si no existe) y secret password cambia la contraseña maestra. Consulta la bóveda.

En una máquina de build no hay bóveda. Pasa el secreto como una variable de entorno llamada ULTRAMAN_SECRET_ seguida de su nombre en mayúsculas, con cada carácter que no sea letra ni dígito convertido en _: api-key se convierte en ULTRAMAN_SECRET_API_KEY. Tiene prioridad sobre la bóveda y no necesita contraseña. Sin --yes, un secreto solo va adonde se haya aprobado.

Variables de entorno #

VariableQué hace
ULTRAMAN_SECRET_<NAME>El valor de un secreto para este comando.
ULTRAMAN_HOMESustituye a ~/.ultraman, donde están la bóveda, la lista de confianza y las claves del servidor.
ULTRAMAN_LOAD_WORKERSLa cantidad de hilos por defecto para una carga (--workers tiene prioridad).
ULTRAMAN_NO_UPDATE_CHECK1 desactiva la comprobación diaria de versiones nuevas.
ULTRAMAN_PROJECTLa carpeta de proyecto con la que se abre la ventana de escritorio.
NO_COLORSalida sin colores.
ULTRAMAN_VERSION, ULTRAMAN_CLI_ONLYPara los instaladores: la versión que se instala, y solo el comando, sin la ventana. Consulta Instalar.

La ventana y la terminal a la vez #

Si la ventana tiene el proyecto abierto, ultraman run le pasa la ejecución: la ves en vivo en la ventana y la terminal muestra lo mismo de siempre. Con --local se ejecuta en la terminal, que es lo que quieres en una máquina de build compartida. Las ejecuciones de CI siempre lo usan.
