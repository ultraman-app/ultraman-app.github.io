Trabalho em equipe #

Tudo o que uma equipe compartilha é um arquivo dentro de ultraman/. Assim, os testes andam junto com o código, e uma mudança num teste aparece num pull request como qualquer outra.

Sincronizar #

Se o projeto está num repositório git com um remoto, a barra superior mostra quantos arquivos faltam sincronizar ("2 alterações não sincronizadas") e oferece Sincronizar. Salvar (Ctrl+S) só grava no seu disco; nada chega ao remoto até você sincronizar.

A sincronização mexe em seis pastas, e só nelas: ultraman/pipelines/, ultraman/blocks/, ultraman/envs/, ultraman/requests/ (as coleções), ultraman/load-tests/ e ultraman/files/ (os arquivos que as requests enviam). Ela faz o commit dessas pastas (o painel lista os arquivos e uma mensagem que você pode editar), busca as mudanças do remoto, faz o merge, dá push e recarrega. O resto do repositório, as outras mudanças que você não commitou e o que está em stage continuam intactos. Ela usa o git do seu sistema e as suas próprias credenciais; o app nunca pede senha.

Conflitos #

Se uma pipeline mudou no seu disco e também no remoto, um diálogo mostra as duas versões lado a lado, como passos ou como YAML. Escolha Ficar com a minha, Usar a do remoto ou Salvar a minha como cópia. Esc cancela sem mudar nada.

Quando a sincronização falha #

A sincronização mostra o motivo e o que o git respondeu. Os casos mais comuns:

MensagemO que fazer
The branch … has no remote configuredFaça o push dela uma vez: git push -u origin <branch>
You have unpushed commits that touch files outside ultraman/Os commits são seus e o Ultraman não dá push neles: execute git push e sincronize de novo
The remote rejected the pushA branch é protegida ou falta permissão. Suas mudanças continuam commitadas localmente: mande-as por uma branch e um pull request
Couldn't fetch the remote'sProblema de rede ou de credenciais: tente git fetch no terminal
Git doesn't know who you aregit config --global user.name "Seu nome" e git config --global user.email voce@email
There's an unfinished merge or rebaseTermine ou aborte o merge ou rebase no terminal

Mudou no disco #

Se você executa git pull num terminal, ou altera um YAML em outro editor, a janela percebe sozinha. Se a pipeline aberta tinha mudanças não salvas, aparece "Mudou no disco enquanto você editava." com a opção Recarregar.

O que fica só com você #

Os seus segredos, os valores de ambiente desta máquina, o histórico, as execuções anteriores e os relatórios de carga nunca são sincronizados. Cada pessoa define os próprios segredos no próprio cofre.

Pastas confiáveis #

A confiança numa pasta é de cada pessoa, em cada máquina. Numa pasta em que você não confiou, o Ultraman não envia nada pela janela e não executa git, então só há sincronização depois que você confiar nela. Isso protege você quando abre um repositório que acabou de clonar de outra pessoa. Confiar é decisão sua e fica no seu computador: nunca é guardado no projeto.

Em pull requests #

Como as pipelines e os testes de carga são YAML, uma mudança num teste aparece como um diff legível: qual passo mudou, qual limiar foi alterado. Uma request vinculada numa pipeline diz de onde veio (from: shop/orders/create).

O que mantém você seguro #

  • Sua equipe: só essas seis pastas entram no commit e no push; segredos, valores locais, histórico e relatórios ficam em cada máquina (o que fica guardado).
  • Você: uma pasta em que você não confiou não envia nada e não executa git (pastas confiáveis).
  • Sua equipe: uma mudança num teste é um diff legível, então um host ou header novo não entra sem ninguém ver.
  • CI: os mesmos arquivos executam no seu pipeline de CI, com os segredos próprios dele (CI).
