Trabalhando em time #

Tudo o que um time compartilha é um arquivo sob ultraman/, então seus testes viajam com o seu código e uma mudança num teste aparece num pull request como qualquer outra mudança.

Sincronizar #

Se o projeto está num repositório git com um remoto, a barra no alto diz quantos arquivos faltam sincronizar ("2 alterações não sincronizadas") e oferece Sincronizar. Salvar (Ctrl+S) só escreve no seu disco; nada chega ao remoto até você sincronizar.

Sincronizar mexe em seis pastas, e só nelas: ultraman/pipelines/, ultraman/blocks/, ultraman/envs/, ultraman/requests/ (as coleções), ultraman/load-tests/ e ultraman/files/ (os arquivos que as requests enviam). Ele faz o commit delas (o painel lista os arquivos e uma mensagem que você pode editar), busca as mudanças do remoto, faz o merge, envia e recarrega. O resto do seu repositório, as suas outras mudanças não commitadas e o que você tem em stage ficam como estão. Usa o git do seu sistema e as suas próprias credenciais; o app nunca pede uma senha.

Conflitos #

Se uma pipeline mudou no seu disco e no remoto, um diálogo mostra as duas versões lado a lado, como passos ou como YAML. Escolha Ficar com a minha, Usar a do remoto ou Salvar a minha como cópia. Esc cancela e não muda nada.

Quando a sincronização falha #

Sincronizar mostra o motivo e o que o git disse. Os mais comuns:

MensagemO que fazer
The branch … has no remote configuredEnvie-a uma vez: git push -u origin <branch>
You have unpushed commits that touch files outside ultraman/São seus e o Ultraman não os envia: git push, e sincronize de novo
The remote rejected the pushUma branch protegida ou falta de permissão. Suas mudanças continuam commitadas localmente: envie-as por uma branch e um pull request
Couldn't fetch the remote'sRede ou credenciais: tente git fetch no terminal
Git doesn't know who you aregit config --global user.name "Seu nome" e git config --global user.email voce@email
There's an unfinished merge or rebaseTermine-o ou aborte-o no terminal

Mudou no disco #

Se você faz git pull num terminal, ou muda um YAML com outro editor, a janela percebe sozinha. Se a pipeline que você tem aberta tinha mudanças não salvas, ela diz "Mudou no disco enquanto você editava" e oferece Recarregar.

O que fica pessoal #

Os seus segredos, os valores de ambiente desta máquina, o histórico, as execuções passadas e os relatórios de carga nunca são sincronizados. Cada pessoa define os próprios segredos no próprio cofre.

Pastas confiáveis #

Uma pasta é confiável por pessoa, naquela máquina. Numa pasta em que você não confiou, o Ultraman não envia nada pela janela e não executa git, então não há sincronização até você confiar nela. Isso protege você quando abre um repositório que acabou de clonar de outra pessoa. Confiar é decisão sua e fica no seu computador: nunca é guardado no projeto.

Em pull requests #

Como as pipelines e os testes de carga são YAML, uma mudança num teste aparece como um diff legível: qual passo mudou, qual limiar se moveu. Uma request vinculada numa pipeline diz de onde veio (from: shop/orders/create).

O que mantém você seguro #

  • Seu time: só essas seis pastas são commitadas e enviadas; segredos, valores locais, histórico e relatórios ficam em cada máquina (o que fica guardado).
  • Você: uma pasta em que você não confiou não envia nada e não executa git (pastas confiáveis).
  • Seu time: uma mudança de teste é um diff legível, então um host ou header novo não passa despercebido.
  • CI: os mesmos arquivos rodam na sua pipeline com os segredos dela (CI).
