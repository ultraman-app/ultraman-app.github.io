Primeiros passos #

Da instalação do Ultraman até a sua primeira request e a sua primeira pipeline, além de como ele se atualiza, por que o seu sistema pode emitir um aviso sobre ele e como removê-lo.

Instalar #

Um único comando instala o app e o comando ultraman para o seu usuário, com tudo o que eles precisam já incluído (inclusive o Node). Não pede permissão de administrador nem conta.

macOS e Linux, num terminal:

curl -fsSL https://ultraman-app.github.io/install.sh | sh

Windows, no PowerShell:

irm https://ultraman-app.github.io/install.ps1 | iex

Antes de instalar qualquer coisa, o script confere se os arquivos são mesmo os que o Ultraman publicou (veja O que é assinado); se não forem, ele para e nada muda.

SistemaO appO comando
macOS (Apple silicon ou Intel)~/Applications/Ultraman.app~/.local/bin/ultraman
Linux (x64)~/.local/share/ultraman/Ultraman.AppImage, no menu de aplicativos~/.local/bin/ultraman
Windows (x64)Menu Iniciar, Ultraman%LOCALAPPDATA%\ultraman-cli, adicionado ao seu PATH
  • No macOS e no Linux, se ~/.local/bin não estiver no seu PATH, o script mostra a linha que você deve acrescentar ao perfil do seu shell. No Windows, abra um terminal novo para ele pegar o PATH atualizado.
  • No Linux, o app é um AppImage e precisa do FUSE: se ele não abrir, instale o libfuse2.

Só o comando, sem o app, para uma máquina de build ou um servidor:

curl -fsSL https://ultraman-app.github.io/install.sh | sh -s -- --cli
$env:ULTRAMAN_CLI_ONLY = 1; irm https://ultraman-app.github.io/install.ps1 | iex

Para instalar uma versão específica em vez da mais recente, acrescente --version <version> depois de -- (macOS, Linux) ou defina ULTRAMAN_VERSION antes (qualquer sistema). No GitHub Actions, a action faz a instalação para você: veja CI.

Abrir um projeto #

Um projeto é qualquer pasta: o Ultraman guarda os arquivos dele numa pasta ultraman/ lá dentro. Em geral é o repositório da API que você testa, assim os testes andam junto com o código. Abra o projeto pelo menu de pastas, no canto superior esquerdo.

Na primeira vez, o Ultraman pergunta se você confia na pasta, porque as pipelines de um projeto decidem para onde as requests vão e as configurações de git dele podem executar comandos na sua máquina:

  • Abrir em modo restrito (o padrão): você pode navegar e editar, mas o Ultraman não envia nada a partir dela nem executa git até você confiar nela.
  • Confiar nesta pasta: só se você souber de onde ela veio. Você responde uma vez por pasta, nesta máquina.

Mais em Pastas confiáveis.

O que fica onde:

O Ultraman cria o ultraman/.gitignore com as pastas que ficam só na sua máquina, para que o git as deixe de fora. Os segredos nem estão no projeto: veja Onde as coisas ficam guardadas.

As duas áreas #

  • Pipelines: fluxos de vários passos, o diagrama, Executar e Carga.
  • Requests: coleções como no Postman, abas, Enviar, histórico e o servidor mock.

Você alterna entre elas no topo. A barra superior também tem o campo Abrir… (Ctrl/Cmd+P), para ir a qualquer coisa pelo nome, e o botão do ambiente: clique nele para ver os valores do ambiente escolhido e trocar de ambiente (ele tem uma cor própria, e nomes com prod ou live sempre aparecem na cor de alerta). O botão ? abre o manual, os atalhos e Sobre o Ultraman (a versão, a licença e os avisos de terceiros). Executar, Carga, Salvar e ⋯ de uma pipeline ficam no cabeçalho dela; o Salvar de uma request fica ao lado do nome.

Sua primeira request #

  1. Vá em Requests e clique em Nova coleção. Dê um nome e um host, como https://api.example.com. Depois você pode trocar isso por {{env.api}}, para que mude conforme o ambiente (veja Ambientes).
  2. No menu da coleção, escolha Nova request. Escreva o método e o path.
  3. Clique em Enviar (ou Ctrl/Cmd+Enter). A resposta aparece embaixo (ou ao lado da request, numa janela larga).
  4. Na resposta, passe o mouse sobre um valor: o menu dele adiciona um check (assert) ou guarda o valor numa variável (extract).
  5. Salvar (Ctrl/Cmd+S).

Sua primeira pipeline #

  1. No menu de uma coleção, escolha Criar pipeline: o Ultraman monta uma com todas as requests dela, com o login primeiro.
  2. Ou, em Pipelines, clique em Nova pipeline e depois em Adicionar passo.
  3. Executar percorre a pipeline de cima para baixo; cada passo mostra o resultado no próprio lugar.

O projeto de exemplo #

Não sabe por onde começar? Na primeira vez que você abre o Ultraman, a tela de boas-vindas oferece Ver o projeto de exemplo. O mesmo projeto também está no menu de projetos, como Abrir o projeto de exemplo, e no terminal, com ultraman sample (mostra o caminho da pasta).

É uma loja pequena: quatro pipelines (ver produtos, fazer um pedido, consultar um pedido e um endpoint instável que falha de propósito, para você ver um passo em vermelho e o motivo), uma coleção shop, um ambiente, um teste de carga, e execuções, um relatório de carga e um histórico já prontos, então todas as telas mostram dados antes de você executar qualquer coisa.

As requests do exemplo vão para https://shop.example. Quem responde esse endereço é uma pequena loja dentro do Ultraman: não tem porta para iniciar, e nada sai para a rede. Qualquer outro host é enviado normalmente.

  • O exemplo fica na pasta do próprio Ultraman (~/.ultraman/sample/, ou dentro de ULTRAMAN_HOME). Ele começa limpo toda vez que você o abre, então as alterações não ficam.
  • Não é um repositório git, então ali não tem Sincronizar, e não vem com segredos: nenhuma das requests que vêm com ele usa o cofre.
  • A barra superior marca o projeto como Projeto de exemplo. Começar o seu próprio projeto escolhe uma pasta sua.
  • Os números de carga dele não servem de benchmark: a loja responde dentro do Ultraman, com um atraso simulado.

Configurações #

A engrenagem da barra superior (ou Ctrl/Cmd+,) abre as Configurações. Cada opção vale assim que você a escolhe:

  • Tamanho: Automático acompanha a largura da janela; ou fixe em 90, 100, 110, 125 ou 150 %.
  • Densidade: espaçamento Confortável ou Compacta.
  • Código: o tamanho dos bodies, do JSON, do YAML e do editor de passos, de 80 a 150 %.
  • Tema: Sistema acompanha o modo claro ou escuro do seu computador sempre que ele muda; ou escolha Escuro, Claro ou Contraste.
  • Movimento: Sistema segue a opção de movimento reduzido do seu computador; ou escolha Normal ou Reduzido.
  • Janelas largas: Lado a lado coloca a request e a resposta uma ao lado da outra numa janela bem larga; Empilhado deixa a resposta embaixo.
  • Idioma: inglês, espanhol ou português.

Essas escolhas ficam guardadas só neste computador: não entram no projeto e o git não as sincroniza. Redefinir volta tamanho, densidade, código, tema, movimento e a opção de janelas largas ao padrão, e mantém o idioma como está.

Atualizações #

Quando a janela abre, o Ultraman pergunta ao GitHub se há uma versão mais nova, no máximo uma vez por dia. Essa pergunta é a única coisa que sai: o GitHub vê o seu endereço IP, e nada sobre você nem sobre os seus projetos. O comando ultraman sozinho, num terminal ou no CI, nunca faz essa pergunta.

  • Se houver uma versão mais nova, ela aparece num cartão no canto inferior esquerdo, com O que mudou e Atualizar e reiniciar. Nada é baixado antes de você clicar.
  • Atualizar e reiniciar espera até que suas mudanças estejam salvas e nada esteja em execução; aí baixa a versão nova, confere a assinatura, instala e reinicia. O comando ultraman é atualizado junto.
  • Agora não esconde o cartão até sair uma versão mais nova.
  • Manualmente: feche o Ultraman e execute de novo o comando de instalação. Ele substitui o app e o comando no mesmo lugar; se algo falhar, a instalação anterior fica como estava.
  • Seus projetos, segredos salvos e respostas de confiança continuam lá: eles ficam nas suas pastas e em ~/.ultraman.
  • Para desligar a verificação, defina ULTRAMAN_NO_UPDATE_CHECK=1 no ambiente a partir do qual o Ultraman é iniciado.

O que é assinado:

  • Atualizações pela janela: só é instalada uma versão assinada com a chave de atualização do Ultraman; a parte pública da chave vem embutida no app. Um download que não confere não é instalado.
  • Os comandos de instalação: baixam a lista de checksums da versão (SHA256SUMS) e a assinatura dela, feita com a chave de release do Ultraman, cuja parte pública está escrita no próprio script. Eles só instalam arquivos que batem com essa lista assinada; caso contrário, param com "nothing was changed".

Mais sobre o que sai da sua máquina em Segurança e consentimento.

Quando o seu sistema avisa #

Os instaladores não são assinados com um certificado da Apple ou da Microsoft: no Windows não têm assinatura, e no macOS têm só uma assinatura ad hoc (sem notarização). Quem protege você, no lugar disso, é a lista assinada de checksums descrita acima.

Com os comandos de instalação não aparece aviso nenhum: o curl e o PowerShell não marcam o arquivo como baixado da internet, e o próprio script confere a assinatura da versão. Se, em vez disso, você baixar um instalador pela página de releases num navegador:

  • O macOS não o abre na primeira vez. Libere em Ajustes do Sistema, Privacidade e Segurança, Abrir mesmo assim.
  • O Windows SmartScreen diz que protegeu o seu PC. Clique em Mais informações e depois em Executar assim mesmo.

Um arquivo baixado manualmente não passa pela conferência do script. Comparar o arquivo com o SHA256SUMS da mesma versão detecta um download corrompido, mas só o script confere também se a própria lista foi assinada pelo Ultraman: prefira os comandos.

Desinstalar #

  • macOS: arraste o Ultraman para fora de ~/Applications e depois apague ~/.local/share/ultraman e ~/.local/bin/ultraman.
  • Linux: apague ~/.local/share/ultraman, ~/.local/bin/ultraman e ~/.local/share/applications/ultraman.desktop.
  • Windows: remova o Ultraman em Configurações, Aplicativos; depois apague %LOCALAPPDATA%\ultraman-cli e tire essa pasta do PATH do seu usuário.

O que continua lá até você mesmo apagar:

  • ~/.ultraman (no Windows, %USERPROFILE%\.ultraman): o seu cofre criptografado, as suas respostas de confiança e alguns arquivos pequenos do próprio Ultraman. Apague essa pasta para remover de vez os segredos salvos.
  • Se você ativou Lembrar neste computador, a chave do cofre está no chaveiro do sistema: escolha Esquecer a senha neste computador no menu do cofre antes de desinstalar, ou apague a entrada io.github.ultraman-app do chaveiro.
  • As pastas ultraman/ dos seus projetos são suas: a desinstalação não mexe nelas.

O que mantém você seguro #

  • Nada da loja sai da sua máquina: o Ultraman responde shop.example por dentro, e esse nome nunca chega à rede, nem mesmo numa consulta DNS. Qualquer outro host sai normalmente, com as mesmas perguntas. Veja o que sai da sua máquina.
  • Nada fica guardado: o exemplo é copiado de novo toda vez que você o abre, e nada dele é enviado para lugar nenhum, porque ele não tem sincronização com git. Veja pastas confiáveis.
  • Sem segredos: o exemplo não traz nenhum, e nenhuma das requests que vêm com ele usa o seu cofre. Veja o cofre.
