Primeiros passos #

Da instalação do Ultraman até a sua primeira request e a sua primeira pipeline, mais como ele se atualiza, por que o seu sistema pode avisar sobre ele e como removê-lo.

Instalar #

Um comando instala o app e o comando ultraman para o seu usuário, com tudo o que eles precisam dentro (o Node incluído). Sem direitos de administrador, sem conta.

macOS e Linux, num terminal:

curl -fsSL https://ultraman-app.github.io/install.sh | sh

Windows, no PowerShell:

irm https://ultraman-app.github.io/install.ps1 | iex

Antes de instalar qualquer coisa, o script confere se os arquivos são os que o Ultraman publicou (veja O que é assinado); se não forem, ele para e nada muda.

SistemaO appO comando
macOS (Apple silicon ou Intel)~/Applications/Ultraman.app~/.local/bin/ultraman
Linux (x64)~/.local/share/ultraman/Ultraman.AppImage, no menu de aplicativos~/.local/bin/ultraman
Windows (x64)Menu Iniciar, Ultraman%LOCALAPPDATA%\ultraman-cli, adicionado ao seu PATH
  • No macOS e no Linux, se ~/.local/bin não estiver no seu PATH, o script mostra a linha para adicionar ao perfil do seu shell. No Windows, abra um terminal novo para que ele enxergue o PATH novo.
  • No Linux o app é um AppImage e precisa do FUSE: se ele não abrir, instale libfuse2.

Só o comando, para uma máquina de build ou um servidor, sem o app:

curl -fsSL https://ultraman-app.github.io/install.sh | sh -s -- --cli
$env:ULTRAMAN_CLI_ONLY = 1; irm https://ultraman-app.github.io/install.ps1 | iex

Uma versão específica em vez da mais recente: adicione --version <version> depois de -- (macOS, Linux), ou defina ULTRAMAN_VERSION antes (qualquer sistema). No GitHub Actions, a action instala para você: veja CI.

Abrir um projeto #

Um projeto é qualquer pasta: o Ultraman guarda seus arquivos numa pasta ultraman/ dentro dela. O comum é ser o repositório da API que você testa, assim os testes viajam junto com o código. Abra pelo menu de pasta, no canto superior esquerdo.

Na primeira vez, o Ultraman pergunta se você confia na pasta, porque as pipelines de um projeto decidem para onde as requests vão e as configurações de git dele podem rodar comandos na sua máquina:

  • Abrir em modo restrito (o padrão): você pode navegar e editar, mas o Ultraman não envia nada a partir dela e não roda git até você confiar.
  • Confiar nesta pasta: só se você sabe de onde ela veio. Você responde uma vez por pasta, nesta máquina.

O Ultraman escreve ultraman/.gitignore com as pastas que ficam na sua máquina, para que o git as deixe de fora. Os segredos nem estão no projeto: veja Onde as coisas ficam guardadas.

As duas áreas #

  • Pipelines: fluxos de vários passos, o diagrama, Executar e Carga.
  • Requests: coleções como no Postman, abas, Enviar, histórico e o servidor mock.

Você alterna entre elas no topo. O seletor de ambiente ao lado escolhe contra qual ambiente (local, staging…) tudo roda; o olho mostra seus valores.

Sua primeira request #

  1. Vá em Requests e clique em Nova coleção. Dê um nome e um host, como https://api.example.com. Depois você pode trocá-lo por {{env.api}}, para que mude com o ambiente (veja Ambientes).
  2. No menu da coleção, Nova request. Escreva o método e o path.
  3. Aperte Enviar (ou Ctrl/Cmd+Enter). A resposta aparece embaixo.
  4. Na resposta, passe o mouse sobre um valor: o menu dele adiciona um check (assert) ou guarda o valor numa variável (extract).
  5. Salvar (Ctrl/Cmd+S).

Sua primeira pipeline #

  1. No menu de uma coleção, Criar pipeline: o Ultraman monta uma com todas as suas requests, o login primeiro.
  2. Ou em Pipelines, Nova pipeline e Adicionar passo.
  3. Executar roda de cima para baixo; cada passo mostra seu resultado no lugar.

Atualizações #

Quando a janela abre, o Ultraman pergunta ao GitHub se existe uma versão mais nova, no máximo uma vez por dia. Essa pergunta é tudo o que sai: o GitHub vê o seu endereço IP, nada sobre você nem sobre os seus projetos. O comando ultraman sozinho, num terminal ou no CI, nunca pergunta.

  • Se há uma versão mais nova, um cartão no canto inferior esquerdo a mostra, com O que mudou e Atualizar e reiniciar. Nada é baixado antes de você clicar.
  • Atualizar e reiniciar espera até suas mudanças estarem salvas e nada estar rodando, então baixa a versão nova, confere a assinatura dela, instala e reinicia. O comando ultraman é atualizado junto.
  • Agora não esconde o cartão até sair uma versão ainda mais nova.
  • À mão: feche o Ultraman e rode de novo o comando de instalação. Ele substitui o app e o comando no lugar; se algo falhar, a instalação anterior fica como estava.
  • Seus projetos, segredos salvos e respostas de confiança ficam: eles vivem nas suas pastas e em ~/.ultraman.
  • Para desligar a verificação, defina ULTRAMAN_NO_UPDATE_CHECK=1 no ambiente de onde o Ultraman é iniciado.

O que é assinado:

  • Atualizações pela janela: só instala uma versão assinada com a chave de atualização do Ultraman; a metade pública da chave está embutida no app. Um download que não bate não é instalado.
  • Os comandos de instalação: baixam a lista de checksums da versão (SHA256SUMS) e a assinatura dela, feita com a chave de release do Ultraman, cuja metade pública está escrita dentro do script. Eles instalam só arquivos que batem com essa lista assinada, e do contrário param com "nothing was changed".

Mais sobre o que sai da sua máquina em Segurança e consentimento.

Quando o seu sistema avisa #

Os instaladores não são assinados com um certificado da Apple ou da Microsoft: no Windows são sem assinatura, no macOS assinados apenas ad hoc (sem notarização). O que protege você no lugar disso é a lista assinada de checksums acima.

Com os comandos de instalação nada avisa: o curl e o PowerShell não marcam o arquivo como baixado da internet, e o script confere a assinatura da versão por conta própria. Se, em vez disso, você baixar um instalador pela página de releases num navegador:

  • O macOS não o abre na primeira vez. Libere em Ajustes do Sistema, Privacidade e Segurança, Abrir mesmo assim.
  • O Windows SmartScreen diz que protegeu o seu PC. Clique em Mais informações, depois em Executar assim mesmo.

Um arquivo baixado à mão não é conferido pelo script. Compará-lo com o SHA256SUMS da mesma versão pega um download quebrado, mas só o script confere também que a própria lista foi assinada pelo Ultraman: prefira os comandos.

Desinstalar #

  • macOS: arraste o Ultraman para fora de ~/Applications, depois apague ~/.local/share/ultraman e ~/.local/bin/ultraman.
  • Linux: apague ~/.local/share/ultraman, ~/.local/bin/ultraman e ~/.local/share/applications/ultraman.desktop.
  • Windows: remova o Ultraman em Configurações, Aplicativos, depois apague %LOCALAPPDATA%\ultraman-cli e tire-o do PATH do seu usuário.

O que fica até você apagar por conta própria:

  • ~/.ultraman (no Windows, %USERPROFILE%\.ultraman): seu cofre criptografado, suas respostas de confiança e alguns arquivos pequenos do próprio Ultraman. Apague-o para remover seus segredos salvos de vez.
  • Se você ativou Lembrar neste computador, a chave do cofre está no chaveiro do seu sistema: escolha Esquecer a senha neste computador no menu do cofre antes de desinstalar, ou apague a entrada io.github.ultraman-app do chaveiro.
  • As pastas ultraman/ dos seus projetos são suas: desinstalar não mexe nelas.
