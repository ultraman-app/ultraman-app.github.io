Agentes (MCP) #

Um agente de IA (Claude Code, ou qualquer outro cliente MCP) pode usar o Ultraman por meio de ultraman mcp. Ele pode fazer o que você faz na janela: ler e escrever requests, pipelines e testes de carga, enviá-los e executá-los, importar, iniciar o servidor mock, ler relatórios e compará-los. Você aprova cada chamada.

Conecte #

ultraman mcp é um servidor MCP por stdio. No Claude Code:

claude mcp add ultraman -- ultraman mcp --project <your project folder>

Qualquer outro cliente MCP aceita a mesma coisa nas suas próprias configurações: um servidor stdio cujo comando é ultraman e cujos argumentos são mcp --project <your project folder>. Sem --project, o projeto é a pasta de onde você o inicia (ou a mais próxima acima dela que tenha ultraman/).

Duas coisas precisam ser verdade, ou cada ferramenta responde "open Ultraman on this project to approve the agent's requests":

  • a janela do Ultraman está aberta nesse projeto, porque é ali que você aprova;
  • a pasta é confiável na janela (pastas confiáveis).

Você aprova cada chamada #

Cada coisa que o agente pede aparece como um cartão no canto inferior direito: quem pede, o quê, e o detalhe (numa mudança, o diff). Aprovar ou Rejeitar (com um motivo que o agente lê). Pedidos só de leitura podem ser aprovados "sempre"; isso dura apenas a sessão atual do agente, e só enquanto o Ultraman continuar aberto.

O que executa (uma pipeline, uma request, uma carga) tem dois cartões: um para iniciar, e outro para entregar o resultado ao agente. O cartão de entrega avisa quando o resultado leva tokens, cookies ou headers de autenticação. Se você rejeita uma entrega, é definitivo.

Uma chamada dura no máximo uns 50 segundos, porque a maioria dos clientes corta uma chamada de ferramenta aos 60: uma execução longa continua e o agente pede o resultado depois. Enquanto um cartão espera por você, o agente recebe um aviso de progresso a cada 5 segundos. Toda request é registrada em ultraman/mcp/, que o git ignora.

Um stream WebSocket ou SSE é enviado uma vez (send_stream, ou uma request de stream salva): ele abre, envia as mensagens do cartão, escuta pelo tempo do cartão (30 segundos no máximo), fecha, e a entrega traz o handshake e as mensagens nos dois sentidos (as primeiras 50, cada uma cortada em 4 KB). O agente não tem uma sessão ao vivo: para uma que fique aberta, use a janela.

O que ele pode fazer #

As ferramentas vêm em áreas que correspondem às da janela:

  • Pipelines e blocos: listar, ler, salvar e executar; ler execuções passadas; transformar um arquivo HAR ou entradas do histórico numa pipeline proposta.
  • Requests: listar, ler e salvar coleções e requests, movê-las e organizá-las, incluir uma numa pipeline, enviar uma request salva com seus checks, executar uma coleção, enviar uma request avulsa, ler o histórico.
  • Streams: envios únicos de WebSocket e SSE.
  • Carga: listar, ler e salvar testes de carga, executar um, ler relatórios, comparar dois, tendência, exportar.
  • Projeto: listar e salvar ambientes, listar segredos (só os nomes), importar um arquivo do Postman, OpenAPI, JMeter ou Artillery, ler a referência do formato YAML.
  • Servidor mock: estado, iniciar, parar, reiniciar, fixar uma gravação.

Uma escrita mostra seu diff (ou o arquivo novo inteiro) no cartão. Um salvamento que liga http simples ou uma CA própria é sinalizado em vermelho.

O que ele não pode fazer #

De propósito, o agente não pode ver nem definir o valor de um segredo, desbloquear o cofre, dar sim a um consentimento, confiar numa pasta, sincronizar com o git, nem apagar nada. Isso fica com você, na janela. Ele pode usar {{secrets.x}}; o valor nunca chega a ele, e os resultados são ocultados antes de serem entregues a ele.

Uma coisa não é um segredo: um token que um passo extrai de uma resposta (por exemplo o access_token de um login) é só dado, então volta ao agente. É por isso que o cartão de entrega destaca tokens, cookies e headers de autenticação antes de você aprovar.

Perguntando as coisas a ele #

O agente lê este mesmo manual (get_manual) e a referência do formato YAML (get_reference), então você pode perguntar "como executo isto com 50 usuários?" ou "faça uma pipeline que faz login e cria um pedido" e ele vai propor a mudança para você aprovar. O que um resultado diz é entregue a ele como dado para ler, não como instruções para seguir.

A aprovação protege o que passa pelo canal MCP. Um agente com um shell (o Claude Code tem um) também pode ler os arquivos do seu projeto ou executar ultraman run por conta própria: isso está fora do alcance do Ultraman. Trate os cartões como consentimento, não como uma sandbox, e dê a um agente só o acesso que você daria a um colega.

O que mantém você seguro #

  • Você: nada do que o agente pede acontece até você aprovar o cartão, e uma entrega rejeitada continua rejeitada (agentes).
  • Você: o agente nunca vê o valor de um segredo e não pode desbloquear o cofre, dar um consentimento, confiar numa pasta, sincronizar nem apagar (a ocultação).
  • Você: o agente não pode se aprovar: uma decisão precisa da janela (servidor local).
  • Seu time: as requests do agente são registradas em ultraman/mcp/, só na sua máquina.
  • Limite: um agente com seu próprio shell está fora dos cartões (limites).
