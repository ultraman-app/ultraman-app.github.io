Histórico de segurança #

Como a segurança do Ultraman foi revisada até agora, em números: o que cada revisão examinou, o que encontrou e o que aconteceu com o que encontrou.

São revisões internas, feitas como parte do desenvolvimento do Ultraman. Ninguém de fora o auditou (Limites honestos). Esta página dá só totais, nunca o detalhe de um problema específico.

Como é uma revisão #

Uma revisão lê o código do lado de quem ataca: o que uma pasta de projeto vinda de outra pessoa, um servidor hostil, uma página web ou outro programa no mesmo computador poderia fazer o Ultraman fazer. Os recursos grandes são revisados enquanto são construídos, e cada versão é revisada antes de sair.

  • Cada achado é registrado com uma gravidade: o julgamento de quem revisa sobre quanto dano ele poderia causar, e com que facilidade.
  • A maioria das correções vem com um teste que falha antes da correção e passa depois, para que o problema não volte sem ninguém perceber.
  • Quando uma revisão encontra algo grave, as correções passam por uma segunda revisão.

Como ler estes números #

  • Eles mostram que as revisões acontecem e que quase tudo o que encontraram está corrigido. Não mostram que não resta nada a encontrar.
  • Mais achados não significam uma área mais fraca: uma área revisada mais vezes, ou mais a fundo, registra mais.
  • Nada disto é uma auditoria externa nem uma certificação.
  • Para relatar um problema, veja a política de segurança: os relatos vão em particular, pelo GitHub.
