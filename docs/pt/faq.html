Perguntas #

Respostas curtas para o que as equipes perguntam antes de adotar o Ultraman, inclusive os "nãos" sinceros. Cada resposta leva à página que entra em mais detalhes.

Confiança e segurança #

Ele pode mandar meu token para o lugar errado? #

Um segredo só vai para uma origem (esquema, host e porta) para a qual você disse sim; na primeira vez que ele iria para um lugar novo, o Ultraman pergunta, inclusive no terminal. Quando um redirecionamento leva a outra origem, as credenciais são descartadas. Numa pasta em que você não confiou, a janela não envia nada e não executa git. Veja Segurança e consentimento.

Um agente de IA consegue ver meus segredos? #

Não. Um agente conectado via MCP pode usar {{secrets.x}}, mas o valor nunca chega até ele, e cada chamada aparece como um cartão na janela, que você aprova ou rejeita. Ele não consegue desbloquear o cofre, dar sim a um host novo, confiar numa pasta, sincronizar com o git nem apagar nada. Um token que um passo extrai de uma resposta é um dado, não um segredo: o cartão que entrega um resultado destaca os tokens antes de você aprovar. Veja Agentes.

Ele envia alguma coisa sobre mim? #

Não há telemetria nem conta. Enquanto a janela está aberta, o Ultraman pergunta ao GitHub, no máximo uma vez por dia, se existe uma versão mais nova, sem enviar nada sobre você nem sobre os seus projetos; ULTRAMAN_NO_UPDATE_CHECK=1 desliga isso. Nada é baixado até você escolher Atualizar e reiniciar. Veja O que sai da sua máquina.

Em quais sistemas ele executa? #

Windows (x64), macOS (Apple silicon e Intel) e Linux (x64, como AppImage). Os instaladores não são assinados pela Microsoft nem pela Apple, então a primeira abertura mostra um aviso; as atualizações e os checksums dos scripts de instalação são assinados. Veja O aviso da primeira abertura.

Como compartilho segredos com a minha equipe? #

Não compartilha. Cada pessoa define os próprios valores no próprio cofre, com os nomes que o ambiente usa (staging.token); o CI recebe os dele via ULTRAMAN_SECRET_*. O repositório guarda só {{secrets.x}}. Veja Segredos.

O que ele faz e o que não faz #

Dá para escrever scripts? #

Não, de propósito: o que um passo faz está sempre na tela, e quem revisa lê tudo num diff sem executar nada. No lugar de scripts, há asserts, extracts (por path JSON, header ou regex), passos if e repeat, blocos reutilizáveis e funções dentro de {{ }}, como random.uuid, now.iso, base64(x) e hmac.sha256(secrets.key, body). Na importação, os scripts de teste comuns do Postman viram checks; os outros scripts aparecem listados para você, e nunca são executados. Veja Ajudantes.

Quais protocolos ele suporta? #

HTTP e HTTPS (com GraphQL), WebSocket e Server-Sent Events (SSE). Os streams funcionam como requests na área de Requests, como passos de pipeline e sob carga. Sem suporte: Socket.IO, WebSockets comprimidos, reconexão automática (conecte de novo, ou escreva a nova tentativa como passos) e mock para streams. Veja Streams.

Ele faz gRPC? #

Não. O Ultraman testa APIs HTTP, incluindo streams WebSocket e SSE; para gRPC, escolha uma ferramenta que tenha suporte (veja Quando escolher outra coisa).

Ele faz GraphQL? #

Sim: uma request pode levar um body GraphQL, com autocompletar a partir do schema da API (carregado do servidor ou salvo no projeto), e uma resposta com errors faz o passo falhar mesmo com status 200, inclusive sob carga. As subscriptions funcionam sobre graphql-transport-ws, na área de Requests e como passos de pipeline. Ainda não: GraphQL sobre SSE, GET e persisted queries, batching e upload de arquivos. Veja GraphQL.

Quais tipos de autenticação? #

Bearer token, basic auth e API key (num header ou na query string), definidos numa request, numa coleção ou numa pipeline. ca faz confiar na autoridade certificadora do seu próprio servidor. Não há certificados de cliente (mTLS), fluxos OAuth2, AWS SigV4 nem NTLM. Para uma API que emite tokens, um passo de login, um extract do token e uma auth bearer que o use resolvem o caso comum. Veja Pipelines.

Dá para trazer o que eu já tenho? #

Sim: coleções e ambientes do Postman, documentos OpenAPI 3, planos .jmx do JMeter, scripts do Artillery e tráfego gravado no navegador como arquivo HAR. Os segredos de um ambiente do Postman vão para o cofre. O que não dá para traduzir aparece listado, não se perde, e uma importação nunca envia uma request nem executa um script. Veja Importar.

Preciso ter Node, Java ou alguma outra coisa instalada? #

Não. O instalador traz tudo, inclusive o Node, para a sua pasta de usuário, sem precisar de permissão de administrador. Veja Instalar.

Dá para usar sem o app desktop? #

Sim: instale só o comando (--cli) numa máquina de build ou num servidor. A janela é onde você responde às perguntas de consentimento e aprova os cartões do agente; sem ela, o comando pergunta no terminal. Veja O terminal.

Equipes e CI #

Quem pode ver e alterar os nossos testes? #

Quem pode ler ou escrever no seu repositório git: o Ultraman não tem contas, papéis nem workspaces próprios. As mudanças nos testes chegam à equipe por Sincronizar e são revisadas como pull requests. Os segredos nunca são sincronizados: cada pessoa guarda os seus no próprio cofre. Veja Trabalho em equipe.

O que acontece quando duas pessoas alteram a mesma pipeline? #

Sincronizar mostra as duas versões lado a lado, como passos ou como YAML, e você escolhe Ficar com a minha, Usar a do remoto ou Salvar a minha como cópia. Esc cancela sem mudar nada. Veja Conflitos.

Funciona no CI? #

Sim. ultraman run executa pipelines, coleções ou testes de carga, gera um relatório JUnit e sai com 0 (passou), 1 (um check ou limiar falhou) ou 2 (não deu para executar). No GitHub, a action ultraman-app/run-action@v1 instala e executa; em outros sistemas, instale só a CLI. O runner não tem cofre: os segredos vêm de variáveis de ambiente ULTRAMAN_SECRET_<NAME>. Veja CI.

Carga #

Um teste de carga pode executar em várias máquinas? #

Não. Uma carga é executada num só computador, numa thread por padrão e em até 8 com --workers. Se você precisa gerar carga a partir de muitas máquinas ou da nuvem, escolha uma ferramenta feita para isso (veja Quando escolher outra coisa).

Quanta carga ele consegue gerar? #

Tanta quanto o seu computador conseguir enviar: depende da máquina, da rede e do peso de cada request. A faixa Este computador acompanha a sua máquina durante a execução e, quando ela foi o gargalo, o veredito diz limited em vez de culpar a API. Veja Mais de uma thread.
