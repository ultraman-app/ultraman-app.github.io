Ambientes e segredos #

Com os ambientes, as mesmas requests executam contra local, staging ou produção; os segredos guardam tokens e senhas no seu computador, criptografados, fora do git e de qualquer log.

Ambientes #

Um ambiente (local, staging, produção) é um conjunto de valores: api: https://staging.example.com. As requests leem esses valores como {{env.api}}. Clique no ambiente no topo para ver os valores e escolher outro na lista; Ambientes…, no fim da lista, abre a edição numa tela própria: os ambientes à esquerda (Novo ambiente) e o escolhido à direita, com as variáveis e as opções de request dele. O cabeçalho tem o caminho de volta para onde você estava, Salvar (com um ponto enquanto houver algo não salvo) e ⋯ com Renomear…, Duplicar… e Apagar ambiente….

Cada valor tem duas metades:

  • o valor compartilhado, em ultraman/envs/<nome>.yaml, sincronizado pelo git;
  • o valor desta máquina, em ultraman/local/envs/<nome>.yaml, que nunca é sincronizado. Use-o para o que só vale para você.

Um valor da máquina vazio significa "igual ao compartilhado". Se tiver valor, ele prevalece sobre o compartilhado em todo lugar: na janela, na CLI e no agente. Se um arquivo de ambiente não puder ser interpretado, o painel mostra o erro e deixa você corrigi-lo como texto.

Importar um arquivo .env #

Importar .env… lê um arquivo .env (KEY=value, export, aspas, comentários) para os valores desta máquina. Nada vai para o arquivo compartilhado, e portanto nada vai para o git, até você mesmo levar o valor para lá. Uma variável que é segredo mantém o valor que tem no cofre.

Veja de onde vem um valor #

Clicar no ambiente no topo abre uma visão rápida dele. Cada variável mostra de onde vem o valor: shared, local, vault ou session. Um segredo sempre aparece como ●●●●.

Embaixo, a sessão lista cada valor que os passos extraíram (ou que você digitou num diálogo), qual passo o gerou e quais passos o usam. O lápis edita o valor desta máquina (vazio volta ao compartilhado). Dá para limpar uma linha da sessão ou a sessão inteira; o valor volta quando o passo que o gera executar de novo. A sessão não é salva: fechar a janela a descarta.

Quando uma request precisa de um valor que o ambiente não tem, um diálogo pede esse valor. Um valor comum pode ficar só nesta sessão, ser salvo no arquivo compartilhado do ambiente (vai para o git) ou ser salvo nesta máquina. Um segredo tem a caixa Salvar nesta máquina: marcada, ele vai para o cofre e nunca para um arquivo.

Opções de request #

Um ambiente também pode ter opções de request: timeouts, redirects, HTTP/2, http simples para um serviço interno sem TLS, ou uma CA própria para um servidor com certificado próprio. Elas ficam em options: no arquivo do ambiente, no compartilhado ou só no desta máquina, e nunca como variável:

# ultraman/envs/internal.yaml
api: http://billing.internal:8080
options:
  plainHttp: true

As opções da própria request prevalecem sobre as da pipeline (ou da coleção), que prevalecem sobre as do ambiente; a aba Opções diz de onde vem um valor herdado. Http simples e CA própria diminuem a proteção do TLS: a janela avisa quando você liga uma delas. Um arquivo de CA fora do projeto pede o seu sim antes do primeiro uso, como qualquer arquivo.

Segredos #

Um segredo é um valor que não pode sair do seu computador: um token, uma senha, uma chave de API. As requests usam o segredo como {{secrets.token}}, e o valor dele:

  • fica num cofre na sua pasta de usuário, criptografado com a sua senha mestra, nunca no repositório;
  • aparece como [secret:token] em respostas, histórico, execuções, exportações e logs;
  • só vai para hosts aos quais você disse sim: na primeira vez que um segredo iria para um host novo, o Ultraman pergunta (veja Segurança e consentimento).

Um valor de ambiente pode apontar para um segredo (token: "{{secrets.token}}"), e assim cada ambiente pode usar o seu. No painel de Ambientes, transforme uma variável em segredo e, depois de um aviso, o valor vai para o cofre; o YAML guarda só a referência. O nome no cofre é, por padrão, <ambiente>.<variável> (por exemplo, staging.token), e você pode mudá-lo. Seus colegas definem os próprios valores nos cofres deles. Renomear atualiza os nomes do cofre que acompanham o nome do ambiente, se o cofre estiver aberto.

Na primeira vez que uma execução precisa de um segredo, a janela pede a senha mestra: para criá-la ou para desbloquear o cofre. O cofre bloqueia de novo depois de 30 minutos sem uso; o cadeado no topo bloqueia o cofre na hora, troca a senha ou a esquece. Como ele é criptografado e o que protege e o que não protege: o cofre.

Se você esquecer a senha mestra, não há como recuperar os segredos. Esqueceu? apaga todos os segredos salvos depois que você digita a confirmação; depois, defina-os de novo.

Lembrar neste computador #

Lembrar neste computador vem desligado e só existe na janela do desktop. Ele guarda a chave do cofre no chaveiro do sistema, para o cofre abrir sem perguntar. É trocar segurança por comodidade: no Windows e no Linux, outros apps que você executa podem ler essa entrada do chaveiro; no macOS, o Keychain pergunta antes. A própria caixa avisa isso. O terminal nunca usa essa chave: a CLI pede a senha mestra por conta própria.

No CI #

Um runner não tem cofre: passe cada segredo como variável de ambiente, ULTRAMAN_SECRET_TOKEN para token (em maiúsculas, e tudo que não for letra ou dígito vira _). Veja O terminal e CI para valores que só existem numa máquina.

O que mantém você seguro #

A promessa vale aqui como em qualquer lugar. O que esta parte acrescenta:

  • Sua equipe: a metade compartilhada de um ambiente fica no git; os valores desta máquina e o cofre, não (o que fica guardado).
  • CI: os segredos vêm de variáveis ULTRAMAN_SECRET_*, então nada sensível fica no repositório (CI).
