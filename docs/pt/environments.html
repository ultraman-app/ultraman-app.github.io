Ambientes e segredos #

Os ambientes deixam as mesmas requests rodarem contra local, staging ou produção, e os segredos mantêm tokens e senhas no seu computador, criptografados, fora do git e de todo log.

Ambientes #

Um ambiente (local, staging, produção) é um conjunto de valores: api: https://staging.example.com. As requests os leem como {{env.api}}. Escolha um no seletor no alto; Ambientes… no fim desse seletor os edita: os ambientes à esquerda (Novo ambiente, Renomear, Duplicar, Apagar), as variáveis do escolhido à direita.

Cada valor tem duas metades:

  • o valor compartilhado, em ultraman/envs/<nome>.yaml, sincronizado pelo git;
  • o valor desta máquina, em ultraman/local/envs/<nome>.yaml, nunca sincronizado. Use para o que vale só para você.

Um valor da máquina vazio quer dizer "igual ao compartilhado". Um com valor vence o compartilhado em todo lugar: a janela, a CLI e o agente. Se um arquivo de ambiente não for lido, o painel mostra o erro e deixa você corrigi-lo como texto.

Importar um arquivo .env #

Importar .env… lê um arquivo .env (KEY=value, export, aspas, comentários) para os valores desta máquina. Nada chega ao arquivo compartilhado, e portanto nada chega ao git, até você mesmo levá-lo para lá. Uma variável que é um segredo mantém o valor que tem no cofre.

Veja de onde vem um valor #

O olho ao lado do seletor de ambiente abre uma espiada no ambiente escolhido. Cada variável diz de onde vem o seu valor: shared, local, vault ou session. Um segredo sempre aparece como ●●●●.

Embaixo, a sessão lista cada valor que os passos extraíram (ou que você digitou num diálogo), qual passo o fez e quais passos o usam. O lápis edita o valor desta máquina (vazio volta ao compartilhado). Uma linha da sessão, ou a sessão inteira, pode ser limpa; ela volta quando o passo que a produz roda de novo. A sessão não é salva: fechar a janela a descarta.

Quando uma request precisa de um valor que o ambiente não tem, um diálogo o pede. Um valor comum pode ficar só para esta sessão, ser salvo no arquivo compartilhado do ambiente (vai para o git) ou ser salvo nesta máquina. Um segredo tem uma caixa Salvar nesta máquina: marcada, ele vai para o cofre e nunca para um arquivo.

Opções de request #

Um ambiente também pode levar opções de request: timeouts, redirecionamentos, HTTP/2, http simples para um serviço interno sem TLS, ou uma CA própria para um servidor com seu próprio certificado. Elas ficam em options: no arquivo do ambiente, compartilhado ou só desta máquina, e nunca como variável:

# ultraman/envs/internal.yaml
api: http://billing.internal:8080
options:
  plainHttp: true

As opções da própria request vencem as da pipeline (ou da coleção), que vencem as do ambiente; a aba Opções diz de onde vem um valor herdado. Http simples e uma CA própria reduzem a proteção do TLS: a janela avisa quando você os liga. Um arquivo de CA fora do projeto pede permissão antes do primeiro uso, como qualquer arquivo.

Segredos #

Um segredo é um valor que não pode sair do seu computador: um token, uma senha, uma chave de API. As requests o usam como {{secrets.token}}, e o valor dele:

  • vive num cofre na sua pasta de usuário, criptografado com a sua senha mestra, nunca no repositório;
  • aparece como [secret:token] nas respostas, no histórico, nas execuções, nas exportações e nos logs;
  • vai só para hosts aos quais você disse sim: na primeira vez que um segredo for a um host novo, o Ultraman pergunta (veja Segurança e consentimento).

Um valor de ambiente pode apontar para um segredo (token: "{{secrets.token}}"), então cada ambiente pode usar o seu. No painel de Ambientes, transforme uma variável em segredo e o valor dela vai para o cofre depois de um aviso; o YAML guarda só a referência. O nome no cofre é, por padrão, <ambiente>.<variável> (por exemplo staging.token) e você pode mudá-lo. Seus colegas definem os valores deles nos cofres deles. Renomear muda os nomes do cofre que seguem o nome do ambiente quando o cofre está aberto.

Na primeira vez que uma execução precisa de um segredo, a janela pede a senha mestra: para criá-la, ou para desbloquear o cofre. O cofre bloqueia de novo depois de 30 minutos parado; o cadeado no alto o bloqueia agora, troca a senha ou a esquece. Como ele é criptografado e o que protege e não protege: o cofre.

Se você esquecer a senha mestra, os segredos não podem ser recuperados. Esqueceu? apaga todos os segredos salvos depois que você digita a confirmação; defina-os de novo em seguida.

Lembrar neste computador #

Lembrar neste computador vem desligado e só existe na janela do desktop. Ele guarda a chave do cofre no chaveiro do seu sistema para que o cofre abra sem perguntar. Troca segurança por comodidade: no Windows e no Linux, outros apps que você executa podem ler a entrada do chaveiro; no macOS o Keychain pergunta antes. A caixa diz isso. O terminal nunca usa essa chave: a CLI pede a senha mestra por conta própria.

No CI #

Um runner não tem cofre: passe cada segredo como variável de ambiente, ULTRAMAN_SECRET_TOKEN para token (maiúsculas, tudo que não for letra ou dígito vira _). Veja O terminal e CI para valores que só existem numa máquina.

O que mantém você seguro #

A promessa vale aqui como em todo lugar. O que esta parte acrescenta:

  • Seu time: a metade compartilhada de um ambiente está no git; os valores desta máquina e o cofre não estão (o que fica guardado).
  • CI: os segredos vêm de variáveis ULTRAMAN_SECRET_*, então nada sensível vive no repositório (CI).
