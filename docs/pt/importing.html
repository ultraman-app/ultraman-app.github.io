Importar #

Os botões ao lado de Nova coleção (área de Requests) trazem o que você já tem: uma exportação do Postman, uma especificação OpenAPI, um plano do JMeter, um script do Artillery ou uma gravação do navegador, para você não começar do zero. Nada no projeto é sobrescrito: um nome já usado ganha -2. No fim, um resumo diz o que entrou, o que foi adaptado, o que precisa de uma mão e quais arquivos foram pulados.

Do Postman #

O botão de importar aceita coleções (v2.0, v2.1), ambientes e globais exportados do Postman. Pastas, requests, bodies, auth (bearer, basic, API key), variáveis e descrições entram como estavam. Os segredos dos ambientes vão para o cofre, nunca para um arquivo. Scripts de teste comuns (status, equals, includes, tempo de resposta, pm.environment.set) viram checks; o resto fica nas Notas da request.

Do OpenAPI #

API aceita um documento OpenAPI 3 (JSON ou YAML) e faz uma coleção: uma request por operação, com bodies de exemplo e checks de contrato (status e formato da resposta).

Do JMeter #

JMX aceita um plano .jmx: uma pipeline por Thread Group, um bloco de preparação a partir de um Once Only Controller, um ambiente a partir das User Defined Variables e um teste de carga com um cenário por grupo. O que não se traduz (scripts, alguns controllers) aparece listado como "precisa de uma mão", com o seu texto.

Do Artillery #

ART aceita um script do Artillery (.yml ou .json): pipelines, blocos antes/depois, ambientes e um teste de carga com as fases como etapas e pesos. Processors e hooks são listados, não executados.

De tráfego gravado #

De um arquivo HAR… (área de Pipelines) transforma uma gravação do navegador numa pipeline. No Chrome ou no Firefox: DevTools › Network › clique direito › Save all as HAR. O Ultraman mantém as chamadas à API, encontra os valores que uma resposta passa para a seguinte (um id, um token) e os transforma em extracts visíveis, para a pipeline voltar a funcionar em vez de repetir valores antigos.

Uma gravação pode conter senhas e tokens: o Ultraman troca por {{secrets.x}} os que ele conhece do seu cofre, mas leia a proposta antes de salvar.

O que uma importação nunca faz #

Uma importação só lê o arquivo que você escolheu e escreve arquivos no seu projeto. Nunca envia uma request, nunca lê nenhum outro arquivo do seu disco, nunca busca um endereço citado dentro do arquivo (um $ref do OpenAPI para uma URL é anotado, não seguido), nunca expande entidades XML num .jmx e nunca executa um script: scripts de teste do Postman, processors do JMeter e hooks do Artillery são listados em "precisa de uma mão" com o seu texto, e só os casos comuns e simples viram checks.

Um arquivo de outra pessoa pode conter qualquer coisa, mas importá-lo é tão seguro quanto abri-lo como texto. Revise o que entrou antes de executar: a primeira execução é o que envia.

O que mantém você seguro #

  • Você: importar não envia nada e não executa nada; a primeira request só sai quando você a envia ou executa, com o sim de sempre para qualquer segredo. Veja consentimento.
  • Você e seu time: os valores secretos de um ambiente do Postman vão para o cofre, nunca para um arquivo do projeto. Num HAR, os valores que batem com o seu cofre viram {{secrets.x}}; leia a proposta antes de salvar, porque uma gravação pode conter senhas que você nunca guardou. Veja o cofre.
  • Você: uma pipeline que veio de fora continua sem poder ler um segredo num check, nem enviar um arquivo de fora de ultraman/files/ sem que ninguém peça. Veja arquivos.
