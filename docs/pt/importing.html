Importar #

O menu Importar ao lado de Nova coleção (área de Requests) traz o que você já tem: uma exportação do Postman, uma spec OpenAPI, um plano do JMeter, um script do Artillery, uma coleção do Bruno, uma exportação do Insomnia ou um servidor MCP; o que fica ao lado de Nova pipeline (área de Pipelines) traz uma gravação do navegador. Assim você não começa do zero. Antes de escrever qualquer coisa, uma prévia mostra o que entraria; no fim, um resumo mostra o que entrou, o que foi adaptado, o que precisa de ajuste manual e quais arquivos foram pulados (uma linha sobre uma request a abre).

Uma só entrada #

Importar › Importar um arquivo ou pasta… (ou Importar uma pasta… para uma coleção do Bruno), ou soltar arquivos ou uma pasta na área de Requests, reconhece o formato pelos próprios arquivos: Postman, Insomnia, Bruno, OpenAPI, JMeter, Artillery ou uma gravação do navegador. Arquivos de formatos diferentes num mesmo envio são recusados, dizendo com o que cada um se parece, e também uma pasta com uma coleção do Bruno e uma exportação de outra ferramenta ao lado. O menu por formato continua lá se você preferir dizer.

Toda importação mostra primeiro uma prévia: cada coleção como Nova coleção ou Atualiza <nome>, o que é novo, o que mudou, o que o arquivo não traz mais, os ambientes e os nomes (nunca os valores) do que vai para o cofre. Nada é escrito até você escolher Importar (ou Atualizar). Um arquivo OpenAPI cuja coleção já existe abre Atualizar a partir da spec. Quando nada dos arquivos pode ser importado (não são a exportação da ferramenta, ou passam de um limite), a prévia diz por quê.

Do Postman #

Importar › Postman aceita coleções (v2.0, v2.1), ambientes e globals exportados do Postman. Pastas, requests, bodies (os de GraphQL com a query e as variáveis), auth (bearer, basic, API key), variáveis e descrições entram como estavam. Os segredos dos ambientes vão para o cofre, nunca para um arquivo. Os scripts de teste comuns (status, equals, includes, tempo de resposta, pm.environment.set) viram checks; o resto fica nas Notas da request.

Do OpenAPI #

Importar › OpenAPI aceita um documento OpenAPI 3 (JSON ou YAML) e cria uma coleção: uma request por operação, com bodies de exemplo e checks de contrato (status e formato da resposta).

Atualizar a partir de uma spec mais nova #

Quando a spec da API muda (uma equipe que gera a spec a partir do código a regenera com frequência), não importe de novo: abra o menu da coleção › Atualizar a partir de uma spec OpenAPI… e escolha o documento mais novo. Uma prévia mostra o que muda (2 novas · 5 atualizadas · 1 fora da spec · 0 precisam de ajuste manual), cada request se abre para mostrar as próprias mudanças, e nada é gravado até você clicar em Aplicar.

Cada operação mantém o seu arquivo de request, então a request mantém o histórico, a base das mudanças de contrato e as respostas do mock. O Ultraman encontra a request pela operação que a importação guardou nela (operation: no arquivo), depois pelo operationId (se o path mudou, ele acompanha) e depois por método e path. Duas requests que reivindicam a mesma operação aparecem numa lista para você resolver; o Ultraman nunca tenta adivinhar.

  • A spec muda: os checks que ela escreveu (marcados com source: openapi), a descrição, o path quando o operationId mudou de lugar, e os parâmetros novos (com os valores de exemplo).
  • Você mantém: o nome, o body, os headers, a auth, as opções, os seus próprios checks, as notas e os valores que você deu aos parâmetros.
  • Operações novas entram do jeito que a importação as escreve. Operações que saíram da spec continuam, com uma linha nas notas e uma marca na árvore; apague-as você mesmo, se quiser.

Uma coleção importada antes desse recurso existir é casada por método e path; os checks de schema que aquela importação copiou aparecem listados, e a prévia oferece removê-los.

De um servidor MCP #

Importar › De um servidor MCP… (área de Requests) transforma o que um servidor MCP oferece em uma coleção. Ele pede o endereço do servidor (https://…/mcp), o ambiente e como se autenticar (um segredo do seu cofre, enviado como bearer ou como um header com o nome que você indicar). O Ultraman abre uma sessão, lê as listas do servidor (ferramentas, recursos, templates de recursos e prompts, quantas páginas forem necessárias, com limites), encerra a sessão e mostra o plano antes de gravar qualquer coisa: o nome e a versão do servidor, cada item e quais ferramentas alteram dados (pelas dicas do próprio servidor). Criar coleção grava. Se o servidor responde 401 ou 403, uma nota sob Auth diz que ele pede autorização: escolha Bearer ou Header de API key, e um segredo.

  • Uma request por ferramenta, numa pasta tools/, com argumentos de exemplo feitos a partir do schema de entrada (os obrigatórios; os opcionais são listados nas notas), a descrição, um check de schema sobre structuredContent quando a ferramenta declara um schema de saída (marcado source: mcp) e as dicas da ferramenta nas notas.
  • Uma request por recurso em resources/ (com o nome dele, ou o endereço). Um template como users://{id}/profile mantém o {id} como texto, com uma nota para trocá-lo: o que o servidor diz nunca lê uma variável sua, então escreva o endereço real (users://42/profile) antes de enviar. Atualizar a partir do servidor continua encontrando essa request: um endereço que combina com o template é a request dele, e mantém o seu endereço.
  • Uma request por prompt em prompts/, com os argumentos obrigatórios preenchidos com o próprio nome como texto de exemplo.
  • A coleção registra o caminho do servidor e guarda as listas em ultraman/files/, para que a sugestão de nomes e o Do servidor funcionem em qualquer máquina.
  • Adaptado lista o que o plano mudou para encaixar: nomes ns/tool de um gateway mantidos como estão, um servidor que diz não ter capabilities mas responde mesmo assim, uma lista de templates que ele recusa, uma lista que parou numa página estranha. O que precisa da sua mão é listado à parte.

A importação é um envio: numa pasta em que você não confia ela recusa, e um segredo indo para um endereço novo pede o seu sim antes. Lê no máximo 2 000 itens no total, as ferramentas primeiro, e o plano diz onde parou. O texto do servidor é mostrado como dado, nunca executado.

Atualizar a partir do servidor #

Uma coleção feita assim tem Atualizar a partir do servidor… no menu, com o ambiente a consultar. Uma prévia mostra o que muda, e nada é gravado até você clicar em Aplicar. Ela nunca pede o segredo de novo: envia com a auth da própria coleção.

  • O servidor muda: a descrição, os checks source: mcp e os novos argumentos obrigatórios (com um exemplo).
  • Você mantém: o nome, os valores de argumentos que você pôs, headers, opções, seus próprios checks e notas. Os argumentos que o schema não tem mais são listados, não removidos.
  • Ferramentas, recursos e prompts novos entram como a importação os escreve; os que sumiram ficam, com uma linha nas notas e uma marca na árvore.

Cada request é encontrada pela marca (a ferramenta, o recurso ou o prompt que ela chama), então uma request renomeada é acompanhada. Um agente pode fazer o mesmo: veja as ferramentas do agente.

Do JMeter #

Importar › JMeter (.jmx) aceita um plano .jmx: uma pipeline por Thread Group, um bloco de preparação a partir de um Once Only Controller, um ambiente a partir das User Defined Variables e um teste de carga com um cenário por grupo. O que não tem tradução (scripts, alguns controllers) aparece na lista como "precisa de ajuste manual", com o texto dele.

Do Artillery #

Importar › Artillery aceita um script do Artillery (.yml ou .json): pipelines, blocos antes/depois, ambientes e um teste de carga com as fases como etapas e pesos. Processors e hooks são listados, não executados.

Do Bruno #

Importar › Bruno aceita uma coleção do Bruno como pasta (escolha a pasta da coleção, a que tem bruno.json ou opencollection.yml), em .bru ou no YAML do Bruno. Só os arquivos da própria coleção são importados: nunca um .env, node_modules ou .git, e no máximo 5.000 arquivos (o resumo avisa se a pasta tinha mais). Para saber se a pasta também tem uma exportação de outra ferramenta, são olhados os primeiros 4 KB de até 200 arquivos JSON, YAML, .jmx ou .har ao lado da coleção; nada deles é importado nem enviado. Pastas, requests, corpos, autenticação (bearer, basic, API key), variáveis, ambientes e descrições entram como estavam; um corpo SPARQL ou de arquivo mantém o tipo de conteúdo com que o Bruno o envia. Uma pasta sem bruno.json nem opencollection.yml é recusada, e isso é dito.

  • Checks: os asserts do Bruno com operadores conhecidos viram checks, e vars:post-response vira extrações. Os demais scripts de teste ficam nas Notas da request.
  • Precisa de ajuste manual: scripts com lógica e OAuth 2 são listados com o texto, nunca executados. Requests gRPC e WebSocket são puladas, e o resumo diz isso.
  • Segredos: um nome em vars:secret vira {{secrets.nome}}, e o resumo lista o ultraman secret set <nome> a executar. Um valor literal de bearer, basic ou API key vai para o cofre, com o nome de onde foi encontrado, nunca para um arquivo; o mesmo vale para um valor literal em um header, parâmetro da query, campo de formulário ou campo do corpo JSON com nome de credencial (Authorization, Cookie, X-Api-Key, Api-Key, ou um nome que termina em token, key, secret, pass ou password). Um valor com outro nome é escrito como estava: revise as requests antes do commit.

Do Insomnia #

Importar › Insomnia aceita uma exportação do Insomnia: v4 (JSON) ou v5 (YAML). Espaços de trabalho, pastas, requests, corpos (com o tipo de conteúdo, como text/yaml), autenticação, ambientes e descrições entram como estavam.

  • Checks e extrações: uma tag {% response %} numa request posterior vira uma extração na request da qual ela lê, e assim o valor passa entre elas à vista.
  • Precisa de ajuste manual: outras tags de template, scripts e OAuth 2 são listados com o texto, nunca executados. Requests gRPC e WebSocket são puladas.
  • Segredos: um valor de ambiente que o Insomnia marca como confidencial, qualquer valor literal de bearer, basic ou API key, e um valor literal em um header, parâmetro da query, campo de formulário ou campo do corpo JSON com nome de credencial (os mesmos nomes do Bruno) vão para o cofre, com o nome de onde foram encontrados. Esses lugares guardam só {{secrets.x}}.

Importar de novo #

Uma coleção que veio do Postman, Bruno ou Insomnia lembra de onde veio. Importe a mesma origem de novo e ela é atualizada no lugar em vez de ficar ao lado como -2:

  • O que é do arquivo (método, endereço, query, headers, body, auth, opções, descrição, o nome e a pasta da request, e os checks que a importação criou) recebe a versão nova do arquivo, a menos que você tenha mudado aqui. Cada request importada guarda uma impressão do que entrou da última vez, assim o Ultraman sabe qual lado mudou.
  • O que você mudou aqui e o arquivo não continua seu. Quando os dois mudaram a mesma coisa, a prévia mostra um conflito com Manter o meu escolhido; escolha Usar o do arquivo para mudar.
  • O que você acrescentou (seus checks, compares, exemplos, notas, um header que o arquivo nunca teve) sempre fica.
  • Uma request que o arquivo não traz mais aparece com Remover desmarcado: deixada, ela fica com uma nota de que o arquivo não a tem mais.
  • Uma request que o arquivo renomeou ou moveu também se move aqui, e as pipelines que a copiam apontam para o lugar novo; seus passos não mudam, então aparecem desatualizadas até você atualizá-las.
  • Um segredo que já está no seu cofre com outro valor no arquivo é uma pergunta: Manter o meu ou Usar o do arquivo. Nenhuma vem escolhida, e Importar espera até cada uma ter resposta. O agente sempre mantém o seu.
  • Uma coleção com o mesmo nome que não veio desta origem (uma que você fez, ou uma de OpenAPI ou MCP) nunca é atualizada a menos que você escolha Atualizar na prévia; Importar como nova é o padrão.
  • Um ambiente também lembra a sua origem (a coleção do Bruno ou o espaço de trabalho do Insomnia com que veio): um ambiente de outra origem com o mesmo nome é a mesma pergunta, com Importar como nova como padrão (entra como staging-2).

De tráfego gravado #

Importar › De um arquivo HAR… (área de Pipelines) transforma uma gravação do navegador numa pipeline. No Chrome ou no Firefox: DevTools › Network › clique com o botão direito › Save all as HAR. O Ultraman fica com as chamadas à API, encontra os valores que uma resposta passa para a próxima (um id, um token) e os transforma em extracts visíveis, para que a pipeline funcione de novo em vez de repetir valores antigos.

Uma gravação pode conter senhas e tokens: o Ultraman troca por {{secrets.x}} os que ele reconhece do seu cofre, mas leia a proposta antes de salvar.

O que uma importação nunca faz #

Uma importação só lê o arquivo que você escolheu e grava arquivos no seu projeto. Ela nunca envia uma request, nunca lê nenhum outro arquivo do seu disco, nunca busca um endereço citado dentro do arquivo (um $ref do OpenAPI para uma URL é anotado, não seguido), nunca expande entidades XML num .jmx e nunca executa um script: scripts de teste do Postman, processors do JMeter e hooks do Artillery aparecem em "precisa de ajuste manual" com o texto deles, e só os casos comuns e simples viram checks.

Um arquivo de outra pessoa pode conter qualquer coisa, mas importá-lo é tão seguro quanto abri-lo como texto. Revise o que entrou antes de executar: é a primeira execução que envia.

O que mantém você seguro #

  • Você: importar não envia nada e não executa nada; a primeira request só sai quando você a envia ou executa, com o sim de sempre para qualquer segredo. Veja consentimento.
  • Você e sua equipe: os valores secretos de um ambiente do Postman vão para o cofre, nunca para um arquivo do projeto. Num HAR, os valores que batem com o seu cofre viram {{secrets.x}}; leia a proposta antes de salvar, porque uma gravação pode ter senhas que você nunca guardou. Veja o cofre.
  • Você: Atualizar a partir de uma spec OpenAPI só grava dentro da pasta daquela coleção e nunca apaga uma request nem o histórico dela; se houver uma request aberta com mudanças não salvas, ela é apontada antes de você aplicar.
  • Você: uma pipeline que veio de fora continua sem poder ler um segredo num check nem enviar, sem perguntar, um arquivo de fora de ultraman/files/. Veja arquivos.
  • Você: importar de um servidor MCP envia só o necessário para ler as listas, nunca chama uma ferramenta, e o plano mostra quais ferramentas alteram dados antes de você criar qualquer coisa. A descrição de uma ferramenta é texto, não uma instrução. Veja consentimento.
  • Você e sua equipe: um segredo vai ao servidor só como o valor do cofre que você escolheu, nunca é gravado num arquivo (só {{secrets.x}}), e um servidor que o repita recebe o valor censurado. O id de sessão nunca é guardado.
  • Você: Atualizar a partir do servidor só grava dentro da pasta daquela coleção e nunca apaga uma request nem o histórico dela.
  • Você e sua equipe: as importações do Bruno e do Insomnia não enviam nem executam nada: scripts e tags de template viram notas. Os segredos (um vars:secret do Bruno, uma credencial literal em um auth ou em um campo com nome de credencial, um valor confidencial do Insomnia) vão para o cofre, nunca para um arquivo. De uma pasta do Bruno só se usam os arquivos da coleção (ao lado, os primeiros 4 KB de até 200 arquivos que parecem exportações, para reconhecer os de outra ferramenta), e .env, node_modules e .git nunca são abertos. Uma pasta escolhida no app de desktop com Importar uma pasta… ou Bruno é lida sem seguir links: um arquivo ou pasta vinculado (um symlink, uma junction do Windows) fica de fora e aparece no resumo. Uma pasta solta na janela, ou escolhida num navegador, é lida pela visualização web, que segue os links: solte ou escolha só uma pasta de confiança, porque um arquivo vinculado dentro dela é lido como se estivesse ali. Uma importação além dos limites (64 coleções ou ambientes, 10.000 valores de ambiente, 50.000 headers) é recusada inteira, com o motivo na prévia e no resumo.
  • Você: nada é escrito antes de você escolher Importar. Importar de novo nunca sobrescreve o que você mudou, nunca remove uma request que você não marcou e nunca troca um valor do seu cofre a menos que você responda Usar o do arquivo.
