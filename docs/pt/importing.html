Importar #

O menu Importar ao lado de Nova coleção (área de Requests) traz o que você já tem: uma exportação do Postman, uma spec OpenAPI, um plano do JMeter ou um script do Artillery; o que fica ao lado de Nova pipeline (área de Pipelines) traz uma gravação do navegador. Assim você não começa do zero. Nada no projeto é sobrescrito: um nome já usado ganha -2. No fim, um resumo mostra o que entrou, o que foi adaptado, o que precisa de ajuste manual e quais arquivos foram pulados.

Do Postman #

Importar › Postman aceita coleções (v2.0, v2.1), ambientes e globals exportados do Postman. Pastas, requests, bodies (os de GraphQL com a query e as variáveis), auth (bearer, basic, API key), variáveis e descrições entram como estavam. Os segredos dos ambientes vão para o cofre, nunca para um arquivo. Os scripts de teste comuns (status, equals, includes, tempo de resposta, pm.environment.set) viram checks; o resto fica nas Notas da request.

Do OpenAPI #

Importar › OpenAPI aceita um documento OpenAPI 3 (JSON ou YAML) e cria uma coleção: uma request por operação, com bodies de exemplo e checks de contrato (status e formato da resposta).

Atualizar a partir de uma spec mais nova #

Quando a spec da API muda (uma equipe que gera a spec a partir do código a regenera com frequência), não importe de novo: abra o menu da coleção › Atualizar a partir da spec… e escolha o documento mais novo. Uma prévia mostra o que muda (2 novas · 5 atualizadas · 1 fora da spec · 0 precisam de ajuste manual), cada request se abre para mostrar as próprias mudanças, e nada é gravado até você clicar em Aplicar.

Cada operação mantém o seu arquivo de request, então a request mantém o histórico, a base das mudanças de contrato e as respostas do mock. O Ultraman encontra a request pela operação que a importação guardou nela (operation: no arquivo), depois pelo operationId (se o path mudou, ele acompanha) e depois por método e path. Duas requests que reivindicam a mesma operação aparecem numa lista para você resolver; o Ultraman nunca tenta adivinhar.

  • A spec muda: os checks que ela escreveu (marcados com source: openapi), a descrição, o path quando o operationId mudou de lugar, e os parâmetros novos (com os valores de exemplo).
  • Você mantém: o nome, o body, os headers, a auth, as opções, os seus próprios checks, as notas e os valores que você deu aos parâmetros.
  • Operações novas entram do jeito que a importação as escreve. Operações que saíram da spec continuam, com uma linha nas notas e uma marca na árvore; apague-as você mesmo, se quiser.

Uma coleção importada antes desse recurso existir é casada por método e path; os checks de schema que aquela importação copiou aparecem listados, e a prévia oferece removê-los.

Do JMeter #

Importar › JMeter (.jmx) aceita um plano .jmx: uma pipeline por Thread Group, um bloco de preparação a partir de um Once Only Controller, um ambiente a partir das User Defined Variables e um teste de carga com um cenário por grupo. O que não tem tradução (scripts, alguns controllers) aparece na lista como "precisa de ajuste manual", com o texto dele.

Do Artillery #

Importar › Artillery aceita um script do Artillery (.yml ou .json): pipelines, blocos antes/depois, ambientes e um teste de carga com as fases como etapas e pesos. Processors e hooks são listados, não executados.

De tráfego gravado #

Importar › De um arquivo HAR… (área de Pipelines) transforma uma gravação do navegador numa pipeline. No Chrome ou no Firefox: DevTools › Network › clique com o botão direito › Save all as HAR. O Ultraman fica com as chamadas à API, encontra os valores que uma resposta passa para a próxima (um id, um token) e os transforma em extracts visíveis, para que a pipeline funcione de novo em vez de repetir valores antigos.

Uma gravação pode conter senhas e tokens: o Ultraman troca por {{secrets.x}} os que ele reconhece do seu cofre, mas leia a proposta antes de salvar.

O que uma importação nunca faz #

Uma importação só lê o arquivo que você escolheu e grava arquivos no seu projeto. Ela nunca envia uma request, nunca lê nenhum outro arquivo do seu disco, nunca busca um endereço citado dentro do arquivo (um $ref do OpenAPI para uma URL é anotado, não seguido), nunca expande entidades XML num .jmx e nunca executa um script: scripts de teste do Postman, processors do JMeter e hooks do Artillery aparecem em "precisa de ajuste manual" com o texto deles, e só os casos comuns e simples viram checks.

Um arquivo de outra pessoa pode conter qualquer coisa, mas importá-lo é tão seguro quanto abri-lo como texto. Revise o que entrou antes de executar: é a primeira execução que envia.

O que mantém você seguro #

  • Você: importar não envia nada e não executa nada; a primeira request só sai quando você a envia ou executa, com o sim de sempre para qualquer segredo. Veja consentimento.
  • Você e sua equipe: os valores secretos de um ambiente do Postman vão para o cofre, nunca para um arquivo do projeto. Num HAR, os valores que batem com o seu cofre viram {{secrets.x}}; leia a proposta antes de salvar, porque uma gravação pode ter senhas que você nunca guardou. Veja o cofre.
  • Você: Atualizar a partir da spec só grava dentro da pasta daquela coleção e nunca apaga uma request nem o histórico dela; se houver uma request aberta com mudanças não salvas, ela é apontada antes de você aplicar.
  • Você: uma pipeline que veio de fora continua sem poder ler um segredo num check nem enviar, sem perguntar, um arquivo de fora de ultraman/files/. Veja arquivos.
