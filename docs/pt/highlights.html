O que o Ultraman te dá #

O Ultraman testa APIs HTTP, incluindo WebSocket e SSE: um só app no seu computador para requests avulsas, testes de vários passos, carga e CI, tudo salvo como arquivos simples no seu próprio repositório git. O Ultraman nunca envia nada de forma insegura sem o seu consentimento explícito: um segredo vai só para um host que você aprovou, e uma pasta em que você ainda não confia não envia nada.

Cada parte abaixo diz o que ela faz por você e onde ler mais. Se preferir começar pelo seu papel, vá para Por onde começar.

Pipelines que se veem #

Uma pipeline é um teste escrito como uma lista de passos: fazer login, pegar o token da resposta, criar um pedido, checar que ele aparece. Você tem um teste que se lê como uma frase: cada passo é uma linha ("token ← $login $.token"), e a mesma pipeline aparece como diagrama, com uma seta da request que produz um valor até a que o usa. Ela é salva como YAML no seu repositório, então uma mudança num teste é revisada num pull request como qualquer outro código. → Pipelines

Requests como no Postman, com memória #

Quando você só quer testar uma chamada: coleções, pastas, abas, Enviar. Cada request guarda seus próprios checks, e cada envio vai para o histórico com o seu tempo, então você vê o que um endpoint respondeu ontem. Quando uma resposta muda de forma em relação à anterior, o Ultraman avisa. Streams WebSocket e SSE abrem numa aba própria. → Requests

Teste de carga de verdade #

A pipeline que você já tem, executada por muitos usuários virtuais ou a uma taxa de chegada fixa: você descobre como a sua API se comporta sob carga sem escrever um segundo teste. Rampas, platôs, tempo de pensar, dados e cookies por usuário, vários cenários misturados por peso, até 8 threads numa só máquina. O relatório dá um veredito em palavras (aguentou, enfileirou, rejeitou requests…) e avisa quando o limite foi o seu próprio computador, e não a API. → Carga

Traga o que você já tem #

Você não começa do zero: coleções e ambientes do Postman, documentos OpenAPI, planos do JMeter, scripts do Artillery e tráfego gravado no seu navegador viram coleções, pipelines, ambientes e testes de carga. O que não dá para traduzir fica listado, não se perde. Uma importação lê só o arquivo que você escolhe e não envia nada. → Importar

Seus segredos vão só aonde você disse #

O Ultraman nunca envia nada de forma insegura sem o seu consentimento explícito. Um segredo, escrito {{secrets.token}}, vive num cofre criptografado no seu computador, nunca no repositório. Na primeira vez que uma request enviaria um segredo para um servidor que você não aprovou para ele, o Ultraman pergunta; o mesmo vale para um arquivo de fora da pasta ultraman/files/ do projeto. Onde o valor de um segredo apareceria (uma resposta, o histórico, um relatório de execução, uma exportação), você vê [secret:token]. Uma pasta em que você ainda não confia abre em modo restrito: não envia nada e não roda git. É isso que permite abrir uma pipeline que um colega escreveu, ou uma da internet, sem que ela mande o seu token para outro lugar sem você saber. O que isso não consegue cobrir está dito com clareza em os limites. → Segurança e consentimento, Ambientes e segredos

Uma equipe que compartilha pelo git #

Sua equipe compartilha testes como compartilha código, sem conta e sem servidor no meio: pipelines, coleções, ambientes, testes de carga e os arquivos que as requests enviam são todos arquivos dentro de ultraman/. Sincronizar faz commit e push só deles, e mostra os conflitos lado a lado. Os segredos, os valores desta máquina e o seu histórico ficam no seu computador. → Trabalho em equipe

Os mesmos testes no CI #

Os testes que você roda na janela podem barrar o seu build. ultraman run executa pipelines, uma coleção ou um teste de carga a partir de um terminal, escreve um relatório JUnit e sai com erro quando um check ou um limiar falha. No GitHub Actions, ultraman-app/run-action o instala e executa; você diz para qual servidor cada segredo pode ir. → CI, O terminal

Seu agente pode usar #

Um agente de IA que fala MCP (o Claude Code, por exemplo) pode criar requests, escrever pipelines, executá-las, iniciar uma carga e ler os relatórios, enquanto você continua no comando: cada chamada mostra um cartão na janela e nada acontece até você aprovar (chamadas só de leitura podem ser liberadas para o resto de uma sessão). O agente pode usar os seus segredos pelo nome, mas nunca vê os valores. → Agentes (MCP)

Uma API falsa feita do que você já enviou #

Quando a API de verdade está fora do ar, lenta ou ainda não foi construída, o servidor mock responde com as respostas que você já gravou, para que um front end ou um teste continue funcionando. Ele responde só no seu computador, a menos que você o inicie pelo terminal e escolha outra coisa. → Servidor mock
