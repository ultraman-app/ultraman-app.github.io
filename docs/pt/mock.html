Servidor mock #

O servidor mock responde às requests da sua API com respostas que você já gravou, para um front end (ou um teste) poder trabalhar enquanto a API real está fora do ar, lenta ou ainda não existe. Ele roda no seu computador e ninguém mais consegue alcançá-lo, a menos que você escolha.

De onde vêm as respostas #

Do Histórico: toda request que você enviou é uma gravação. No Histórico, abra Servidor mock: ele lista as rotas que sabe responder (método e path, com parâmetros de path) para o ambiente escolhido.

Iniciar #

Escolha uma porta e Iniciar (4300 por padrão). Ele responde só nesta máquina, e só inicia numa pasta confiável (o terminal pergunta).

  • Atraso gravado responde tão devagar quanto a API real respondeu.
  • Encaminhar o resto para envia a um host real o que não tem gravação.
  • Uma rota com várias gravações responde com a mais nova; fixe uma específica, ou use Em ordem para passar por elas uma a uma (Reiniciar sequências começa de novo).

Qual gravação responde #

Uma request é comparada nesta ordem, e vale a primeira que bater:

  1. o mesmo método, path e query (a ordem dos parâmetros da query não importa);
  2. o mesmo método e path, qualquer query;
  3. o modelo de path da request: /users/:userId/orders responde /users/u_bob/orders com a gravação de u_ana.

Sem nenhuma correspondência, o mock responde 404 com as rotas conhecidas. Se uma rota tem várias gravações, a mais nova responde, a menos que você fixe uma ou escolha Em ordem. Só as gravações do ambiente escolhido são servidas, e um novo envio é percebido sem reiniciar. Cada resposta leva headers x-ultraman-mock que dizem qual gravação foi, e uma resposta grande demais ou binária é cortada ou vem vazia, com um header que avisa. Cookies e tokens que a API real definiu são servidos como foram gravados.

Pelo terminal #

ultraman mock --env local --port 4300 inicia o mesmo servidor sem a janela; --proxy <url> encaminha o resto.

Para deixar outros computadores da sua rede alcançá-lo, o terminal tem --expose. Ele não está na janela e um agente não consegue ligá-lo. O Ultraman avisa que qualquer pessoa na sua rede pode ler as respostas, que podem conter dados reais, e espera um Enter (ou --yes). Com --proxy também, avisa que qualquer pessoa na sua rede, e qualquer página web aberta ali, poderia chamar aquela API por esta máquina com o acesso desta máquina. A escolha segura é deixar o --expose de fora.

O que mantém você seguro #

  • Você: o mock escuta só em 127.0.0.1 e responde só a requests que nomeiam esta máquina. Uma página web de outro site recebe uma recusa, então um site que você visita não consegue ler as suas gravações nem alcançar uma API pelo --proxy.
  • Você: o --proxy encaminha só para o endereço que você der, e não acrescenta credenciais próprias.
  • Seu time: as gravações vêm do seu histórico pessoal, que nunca é sincronizado. Os segredos nele já estão escondidos como [secret:x]. Veja onde as coisas ficam guardadas e o servidor local.
  • Você: o --expose é uma escolha deliberada e avisada no terminal. Veja os limites.
