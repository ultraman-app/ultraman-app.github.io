Servidor mock #

O servidor mock responde às requests da sua API com respostas que você já gravou. Assim, um front end (ou um teste) continua funcionando enquanto a API real está fora do ar, lenta ou ainda nem existe. Ele funciona no seu computador, e ninguém mais tem acesso a ele, a não ser que você queira.

De onde vêm as respostas #

Do Histórico: cada request que você enviou vira uma gravação. No Histórico, abra Servidor mock: ali aparecem as rotas que ele sabe responder (método e path, com os parâmetros de path) no ambiente escolhido.

Iniciar #

Escolha uma porta e clique em Iniciar (a padrão é 4300). Ele só responde nesta máquina e só inicia numa pasta confiável (o terminal pergunta).

  • Atraso gravado faz o mock responder tão devagar quanto a API real respondeu.
  • Encaminhar o resto para manda para um host real tudo o que não tem gravação.
  • Quando uma rota tem várias gravações, responde a mais nova. Dá para fixar uma específica, ou escolher Em ordem para passar por elas uma a uma (Reiniciar sequências volta ao começo).

Qual gravação responde #

A request é comparada nesta ordem, e vale a primeira que bater:

  1. mesmo método, path e query (a ordem dos parâmetros da query não importa);
  2. mesmo método e path, com qualquer query;
  3. o modelo de path da request: /users/:userId/orders responde a /users/u_bob/orders com a gravação de u_ana.

Se nada bater, o mock responde 404 com a lista das rotas conhecidas. Se a rota tem várias gravações, responde a mais nova, a não ser que você fixe uma ou escolha Em ordem. Só as gravações do ambiente escolhido são servidas, e um envio novo entra sem precisar reiniciar. Cada resposta traz headers x-ultraman-mock dizendo de qual gravação ela veio; uma resposta grande demais ou binária sai cortada ou vazia, com um header avisando. Cookies e tokens que a API real definiu são servidos do jeito que foram gravados.

Pelo terminal #

ultraman mock --env local --port 4300 inicia o mesmo servidor sem a janela; --proxy <url> encaminha o resto.

Para outros computadores da sua rede conseguirem acessá-lo, o terminal tem --expose. Essa opção não existe na janela, e um agente não consegue ligá-la. O Ultraman avisa que qualquer pessoa na sua rede pode ler as respostas, que podem ter dados reais, e espera um Enter (ou --yes). Se você também usar --proxy, ele avisa que qualquer pessoa na sua rede, e qualquer página web aberta ali, poderia chamar aquela API através desta máquina, com o acesso desta máquina. O seguro é deixar o --expose de fora.

O que mantém você seguro #

  • Você: o mock escuta só em 127.0.0.1 e só responde a requests cujo host é esta máquina. Uma página web de outro site recebe uma recusa, então um site que você visita não consegue ler as suas gravações nem chegar a uma API pelo --proxy.
  • Você: o --proxy só encaminha para o endereço que você informar e não acrescenta credenciais por conta própria.
  • Sua equipe: as gravações vêm do seu histórico pessoal, que nunca é sincronizado. Os segredos ali já aparecem ocultos como [secret:x]. Veja onde as coisas ficam guardadas e o servidor local.
  • Você: o --expose é uma escolha deliberada, feita no terminal e com aviso. Veja os limites.
