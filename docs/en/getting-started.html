Getting started #

From installing Ultraman to your first request and your first pipeline, plus how it updates, why your system may warn about it, and how to remove it.

Install #

One command installs the app and the ultraman command for your user, with everything they need inside (Node included). No admin rights, no account.

macOS and Linux, in a terminal:

curl -fsSL https://ultraman-app.github.io/install.sh | sh

Windows, in PowerShell:

irm https://ultraman-app.github.io/install.ps1 | iex

Before it installs anything, the script checks that the files are the ones Ultraman released (see What is signed); if they aren't, it stops and nothing changes.

SystemThe appThe command
macOS (Apple silicon or Intel)~/Applications/Ultraman.app~/.local/bin/ultraman
Linux (x64)~/.local/share/ultraman/Ultraman.AppImage, in your applications menu~/.local/bin/ultraman
Windows (x64)Start menu, Ultraman%LOCALAPPDATA%\ultraman-cli, added to your PATH
  • On macOS and Linux, if ~/.local/bin isn't on your PATH, the script prints the line to add to your shell's profile. On Windows, open a new terminal so it sees the new PATH.
  • On Linux the app is an AppImage and needs FUSE: if it doesn't open, install libfuse2.

Only the command, for a build machine or a server, without the app:

curl -fsSL https://ultraman-app.github.io/install.sh | sh -s -- --cli
$env:ULTRAMAN_CLI_ONLY = 1; irm https://ultraman-app.github.io/install.ps1 | iex

A given version instead of the latest: add --version <version> after -- (macOS, Linux), or set ULTRAMAN_VERSION first (any system). In GitHub Actions, the action installs it for you: see CI.

Open a project #

A project is any folder: Ultraman keeps its files in an ultraman/ folder inside it. Usually that's the repo of the API you test, so the tests travel with the code. Open it from the folder menu at the top left.

The first time, Ultraman asks whether you trust the folder, because a project's pipelines decide where requests go and its git settings can run commands on your machine:

  • Open in restricted mode (the default): you can browse and edit, but Ultraman sends nothing from it and runs no git until you trust it.
  • Trust this folder: only if you know where it came from. You answer once per folder, on this machine.

More in Trusted folders.

The two areas #

  • Pipelines: multi-step flows, the diagram, Run and Load.
  • Requests: collections like in Postman, tabs, Send, history and the mock server.

Switch between them at the top. The environment selector next to them chooses which environment (local, staging…) everything runs against; the eye shows its values.

Your first request #

  1. Go to Requests and click New collection. Give it a name and a host, like https://api.example.com. Later you can replace that with {{env.api}}, so it changes with the environment (see Environments).
  2. In the collection's menu, New request. Write the method and the path.
  3. Press Send (or Ctrl/Cmd+Enter). The response shows below.
  4. In the response, hover a value: its menu adds a check (assert) or takes the value into a variable (extract).
  5. Save (Ctrl/Cmd+S).

Your first pipeline #

  1. In a collection's menu, Create pipeline: Ultraman builds one with all its requests, the login first.
  2. Or in Pipelines, New pipeline and Add step.
  3. Run runs it top to bottom; each step shows its result in place.

Updates #

When the window opens, Ultraman asks GitHub whether a newer release exists, at most once a day. That question is all that goes out: GitHub sees your IP address, nothing about you or your projects. The ultraman command on its own, in a terminal or in CI, never asks.

  • If there is a newer version, a card in the bottom-left corner shows it, with What's new and Update and restart. Nothing downloads before you click.
  • Update and restart waits until your changes are saved and nothing is running, then downloads the new version, checks its signature, installs it and restarts. The ultraman command is updated with it.
  • Not now hides the card until a newer version comes out.
  • By hand: close Ultraman and run the install command again. It replaces the app and the command in place; if anything fails, the previous install stays as it was.
  • Your projects, saved secrets and trust answers stay: they live in your folders and in ~/.ultraman.
  • To turn the check off, set ULTRAMAN_NO_UPDATE_CHECK=1 in the environment Ultraman starts from.

What is signed:

  • Updates from the window: only a build signed with Ultraman's update key installs; the key's public half is built into the app. A download that doesn't match is not installed.
  • The install commands: they download the release's list of checksums (SHA256SUMS) and its signature, made with Ultraman's release key, whose public half is written inside the script. They install only files that match that signed list, and stop with "nothing was changed" otherwise.

More on what leaves your machine in Security and consent.

When your system warns #

The installers are not signed with an Apple or Microsoft certificate: on Windows they're unsigned, on macOS signed only ad hoc (not notarized). What protects you instead is the signed list of checksums above.

With the install commands nothing warns: curl and PowerShell don't mark the file as downloaded from the internet, and the script checks the release's signature itself. If you download an installer from the releases page in a browser instead:

  • macOS won't open it the first time. Allow it in System Settings, Privacy & Security, Open Anyway.
  • Windows SmartScreen says it protected your PC. Click More info, then Run anyway.

A file downloaded by hand isn't checked by the script. Comparing it with SHA256SUMS from the same release catches a broken download, but only the script also checks that the list itself is signed by Ultraman: prefer the commands.

Uninstall #

  • macOS: drag Ultraman out of ~/Applications, then delete ~/.local/share/ultraman and ~/.local/bin/ultraman.
  • Linux: delete ~/.local/share/ultraman, ~/.local/bin/ultraman and ~/.local/share/applications/ultraman.desktop.
  • Windows: remove Ultraman in Settings, Apps, then delete %LOCALAPPDATA%\ultraman-cli and take it out of your user PATH.

What stays until you delete it yourself:

  • ~/.ultraman (on Windows, %USERPROFILE%\.ultraman): your encrypted vault, your trust answers and a few small files of Ultraman's own. Delete it to remove your saved secrets for good.
  • If you turned on Remember on this machine, the vault's key is in your system's keychain: choose Forget the password on this machine in the vault's menu before uninstalling, or delete the io.github.ultraman-app entry from the keychain.
  • Your projects' ultraman/ folders are yours: uninstalling doesn't touch them.
