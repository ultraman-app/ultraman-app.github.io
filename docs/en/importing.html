Importing #

The buttons next to New collection (Requests area) bring in what you already have: a Postman export, an OpenAPI spec, a JMeter plan, an Artillery script or a browser recording, so you don't start from zero. Nothing in the project is overwritten: a name that's taken gets -2. At the end, a summary says what came in, what was adapted, what needs a hand, and which files were skipped.

From Postman #

The import button takes collections (v2.0, v2.1), environments and globals exported from Postman. Folders, requests, bodies, auth (bearer, basic, API key), variables and descriptions come in as they were. Environment secrets go to the vault, never to a file. Common test scripts (status, equals, includes, response time, pm.environment.set) become checks; the rest stays in the request's Notes.

From OpenAPI #

API takes an OpenAPI 3 document (JSON or YAML) and makes a collection: a request per operation, with example bodies and contract checks (status and response shape).

From JMeter #

JMX takes a .jmx plan: a pipeline per Thread Group, a setup block from a Once Only Controller, an environment from the User Defined Variables, and a load test with a scenario per group. What doesn't translate (scripts, some controllers) is listed as "needs a hand" with its text.

From Artillery #

ART takes an Artillery script (.yml or .json): pipelines, before/after blocks, environments and a load test with its phases as stages and weights. Processors and hooks are listed, not run.

From recorded traffic #

From a HAR file… (Pipelines area) turns a browser recording into a pipeline. In Chrome or Firefox: DevTools › Network › right click › Save all as HAR. Ultraman keeps the API calls, finds the values one response gives the next (an id, a token) and makes them visible extracts, so the pipeline works again instead of replaying old values.

A recording can contain passwords and tokens: Ultraman replaces the ones it knows from your vault with {{secrets.x}}, but read the proposal before saving.

What an import never does #

An import only reads the file you chose and writes files into your project. It never sends a request, never reads any other file on your disk, never fetches an address named inside the file (an OpenAPI $ref to a URL is noted, not followed), never expands XML entities in a .jmx and never runs a script: Postman test scripts, JMeter processors and Artillery hooks are listed under "needs a hand" with their text, and only the common, plain cases become checks.

A file from someone else can contain anything, but importing it is as safe as opening it as text. Review what came in before you run it: the first run is what sends.

What keeps you safe #

  • You: importing sends nothing and runs nothing; the first request goes out only when you send or run it, with the usual yes for any secret. See consent.
  • You and your team: secret values in a Postman environment go to the vault, never to a file in the project. In a HAR, values that match your vault become {{secrets.x}}; read the proposal before saving, since a recording can hold passwords you never stored. See the vault.
  • You: a pipeline that came from outside still can't read a secret into a check, or send a file from outside ultraman/files/ unasked. See files.
