Working as a team #

Everything a team shares is a file under ultraman/, so your tests travel with your code and a change to a test shows up in a pull request like any other change.

Sync #

If the project is in a git repo with a remote, the top bar says how many files are left to sync ("2 changes not synced") and offers Sync. Saving (Ctrl+S) only writes to your disk; nothing reaches the remote until you sync.

Sync touches six folders, and only those: ultraman/pipelines/, ultraman/blocks/, ultraman/envs/, ultraman/requests/ (the collections), ultraman/load-tests/ and ultraman/files/ (the files requests send). It commits them (the panel lists the files and a message you can edit), fetches the remote's changes, merges them, pushes and reloads. The rest of your repo, your other uncommitted changes and what you have staged are left alone. It uses your system's git and your own credentials; the app never asks for a password.

Conflicts #

If a pipeline changed on your disk and on the remote, a dialog shows both versions side by side, as steps or as YAML. Choose Keep mine, Use the remote's, or Save mine as a copy. Esc cancels and changes nothing.

When sync fails #

Sync shows the reason and what git said. The usual ones:

MessageWhat to do
The branch … has no remote configuredPush it once: git push -u origin <branch>
You have unpushed commits that touch files outside ultraman/They're yours and Ultraman doesn't push them: git push, then sync again
The remote rejected the pushA protected branch or no permission. Your changes stay committed locally: push them through a branch and a pull request
Couldn't fetch the remote'sNetwork or credentials: try git fetch in the terminal
Git doesn't know who you aregit config --global user.name "Your name" and git config --global user.email you@email
There's an unfinished merge or rebaseFinish it or abort it in the terminal

Changed on disk #

If you git pull in a terminal, or change a YAML with another editor, the window notices by itself. If the pipeline you have open had unsaved changes, it says "It changed on disk while you were editing it" and offers Reload.

What stays personal #

Your secrets, this machine's environment values, the history, past runs and load reports are never synced. Each person sets their own secrets in their own vault.

Trusted folders #

A folder is trusted per person, on that machine. In a folder you haven't trusted, Ultraman sends nothing from the window and runs no git, so there is no sync until you trust it. That protects you when you open a repo you just cloned from someone else. Trusting is your decision and stays on your computer: it is never stored in the project.

In pull requests #

Because pipelines and load tests are YAML, a change to a test shows as a readable diff: which step changed, which threshold moved. A linked request in a pipeline says where it came from (from: shop/orders/create).

What keeps you safe #

  • Your team: only those six folders are committed and pushed; secrets, local values, history and reports stay on each machine (what is stored).
  • You: a folder you haven't trusted sends nothing and runs no git (trusted folders).
  • Your team: a test change is a readable diff, so a new host or header can't slip in unseen.
  • CI: the same files run in your pipeline with their own secrets (CI).
