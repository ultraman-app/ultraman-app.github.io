Working as a team #

Everything a team shares is a file under ultraman/, so your tests travel with your code and a change to a test shows up in a pull request like any other change.

Sync #

If the project is in a git repo with a remote, the top bar says how many files are left to sync ("2 changes not synced") and offers Sync. Saving (Ctrl+S) only writes to your disk; nothing reaches the remote until you sync.

Sync touches six folders, and only those: ultraman/pipelines/, ultraman/blocks/, ultraman/envs/, ultraman/requests/ (the collections), ultraman/load-tests/ and ultraman/files/ (the files requests send). It commits them (the panel lists the files and a message you can edit), fetches the remote's changes, merges them, pushes and reloads. The rest of your repo, your other uncommitted changes and what you have staged are left alone. It uses your system's git and your own credentials; the app never asks for a password.

Conflicts #

If a pipeline changed on your disk and on the remote, a dialog shows both versions side by side, as steps or as YAML. Choose Keep mine, Use the remote's, or Keep both (yours is saved beside it as <name>-mine, for pipelines, requests, environments, load tests and copied files alike; it never writes over another file). Esc cancels and changes nothing. Whatever you choose, the version that lost stays in the file's history.

When sync fails #

Sync shows the reason and what git said. The usual ones:

MessageWhat to do
The branch … has no remote configuredPush it once: git push -u origin <branch>
You have unpushed commits that touch files outside ultraman/They're yours and Ultraman doesn't push them: git push, then sync again
The remote rejected the pushA protected branch or no permission. Your changes stay committed locally: push them through a branch and a pull request
Couldn't fetch the remote'sNetwork or credentials: try git fetch in the terminal
Git doesn't know who you aregit config --global user.name "Your name" and git config --global user.email you@email
There's an unfinished merge or rebaseFinish it or abort it in the terminal

Changed on disk #

If you git pull in a terminal, or change a YAML with another editor, the window notices by itself: it checks the files you have open when it gets the focus, when you switch tabs, before every Save and every 5 seconds. A file without unsaved changes simply shows the new version. If a request, pipeline or environment you have open had unsaved changes, it says "It changed on disk while you were editing it" and offers four choices:

  • Keep mine: your version stays; Save writes it over the disk's.
  • Take the disk's: the editor shows the file as it is now. Your unsaved version is set aside in the file's history.
  • Keep both: yours is saved as a new file beside it (<name>-mine), and the editor shows the disk's.
  • Diff: both versions side by side, with the same three choices.

Nothing you choose loses a version: the other one stays in the file's history.

Unsaved work comes back #

While a request, pipeline, environment or load test has unsaved changes, Ultraman keeps a draft of it on this computer. If the window closes, crashes or reloads, the tab comes back with your changes and the note "Restored your unsaved changes"; Discard them goes back to the file (the draft is set aside in its history). A draft goes when you save or discard. If the file changed on disk meanwhile, you get the four choices above.

A file's history #

Before Ultraman writes over or deletes a file in a project folder (a Save, Sync, the agent, an import, a Restore), it keeps the version it replaces; when a file changes outside Ultraman, it keeps the last version it knew. Versions of this file… in its ⋯ menu (a request's in the tree, a pipeline's and an environment's beside Save) opens the file's versions and its git commits in one list: pick one to see it beside the file as it is now, and Restore this version writes it back byte for byte. Recently deleted… (in a collection's ⋯ menu, or beside This file in the same window) lists the files Ultraman or the disk removed, with Restore. Each file keeps up to 20 versions, for 30 days, in Ultraman's own folder on this computer (~/.ultraman), never in the project.

If another program holds a file open (an editor, an antivirus scan), Save waits up to two seconds, then says so and offers Retry; the file stays as it was.

What stays personal #

Your secrets, this machine's environment values, the history, past runs and load reports are never synced. Each person sets their own secrets in their own vault.

Trusted folders #

A folder is trusted per person, on that machine. In a folder you haven't trusted, Ultraman sends nothing from the window and runs no git, so there is no sync until you trust it. That protects you when you open a repo you just cloned from someone else. Trusting is your decision and stays on your computer: it is never stored in the project.

In pull requests #

Because pipelines and load tests are YAML, a change to a test shows as a readable diff: which step changed, which threshold moved. A linked request in a pipeline says where it came from (from: shop/orders/create).

What keeps you safe #

  • Your team: only those six folders are committed and pushed; secrets, local values, history and reports stay on each machine (what is stored).
  • You: drafts and a file's past versions live in Ultraman's own folder on this computer (~/.ultraman), outside the project: git never sees them, a commit can't plant one, and neither the agent nor the CLI reads them.
  • You: a folder you haven't trusted sends nothing and runs no git (trusted folders).
  • Your team: a test change is a readable diff, so a new host or header can't slip in unseen.
  • CI: the same files run in your pipeline with their own secrets (CI).
