Format reference (YAML) #

Everything lives as YAML under ultraman/ in the user's project. Unknown keys are errors: write only what's listed. Variables: {{env.x}} (the environment), {{secrets.x}} (a secret: usable, never visible), {{x}} (an input, an extract or a collection variable).

Durations are written two ways, by field. In pipelines, steps, options and stream files every time is a plain integer of milliseconds (timeout: 10000, wait: 500, listen: 2000); 10s is an error there. In load tests (for, pacing, thinkTime, thresholds, maxWait, apdex) a duration is text such as 500ms, 30s, 1.5m or 1h, and a bare number there is seconds, so p95: 500 means 500 seconds: write the unit. A wait step is milliseconds; a load test's thinkTime is a duration (2s).

Required and allowed keys:

  • A pipeline or block needs name, host and steps. The only other top-level keys are description, tags, auth, options, headers, inputs and exports.
  • A request step needs method and path. The path has no ? (put the query in query), and every :param in it needs a key in params (and every key in params a :param).
  • A request has one body key at most: json, body, form, multipart or file.
  • In a step's query, headers, form and multipart, a key that starts with ~ is a disabled row: it is kept in the file and not sent (~x-debug: "1").

Pipeline (ultraman/pipelines/<id>.yaml) and block (ultraman/blocks/<id>.yaml) #

name: create order                # the id comes from the name (slug)
description: log in and create an order
tags: [orders]
host: "{{env.api}}"               # every request's path goes after it
auth: { bearer: "{{token}}" }     # or { basic: { user, password } }, { apiKey: { name, value, in: header|query } }; per step `auth: none`
headers: { x-tenant: acme }       # sent by every request (a step's own header wins)
inputs: [user]                    # values the run asks for (a block's are filled with `use … with`)
exports: [token]                  # a block's values the caller gets
options: { timeout: 10000, redirects: 5, maxSize: 5242880, http2: false }   # plainHttp / ca relax TLS: the user is warned
steps: [ ... ]

Steps (each starts with its kind) #

- request: login                  # a name others refer to as $login
  description: optional
  method: POST                    # GET POST PUT PATCH DELETE HEAD OPTIONS or a custom token
  path: /users/:id                # :id comes from params
  params: { id: "{{user_id}}" }
  query: { tag: [a, b] }          # a list repeats the key
  headers: { Content-Type: text/plain }
  json: { user: "{{env.test_user}}" }   # one body: json | body (text) | form | multipart | file | graphql
  # form: { name: Ana, tag: [a, b] }
  # multipart: { comment: hi, logo: { file: ultraman/files/logo.png, type: image/png } }
  # file: ultraman/files/note.txt # from ultraman/files/ it goes unasked; any other file asks once
  # graphql:                      # POST only; sent as JSON { query, variables, operationName }
  #   query: "query Order($id: ID!) { order(id: $id) { status } }"   # sent as written: no {{ }} in it
  #   variables: { id: "{{order_id}}" }   # rendered like json
  #   operationName: Order        # when the query has several operations
  #   allowErrors: true           # without it, an answer with `errors` fails the step (even a 200)
  idempotent: true                # under load, reports whether it always answered the same
  # idempotent: { ignore: [$.updatedAt, $.meta.requestId] }   # the same, leaving out the fields that change

- extract: token                  # sets {{token}}
  from: $login
  path: $.token                   # JSONPath; or header: location; or regex: 'id="(\d+)"' (group 1)
  optional: true                  # nothing found = unset, not a failure

- assert: status                  # see "Checks"
  of: $login
  equals: 200

- wait: 500                       # milliseconds

- repeat: 3                       # or a list as text: repeat: "{{ids}}" with as: id
  steps: [ ... ]

- if: { exists: coupon }          # or { equals: [a, b] }, { matches: [text, /re/] }; no else
                                 # a condition, an assert, a `where` or a `regex` never reads a secret, a value made
                                 # from one (a block's export, an extract of an echo) or an echo of one: refused
  steps: [ ... ]

- use: login                      # a block, with its inputs
  with: { user: "{{env.test_user}}" }

- parallel: queries               # branches run at once; later steps wait for all
  branches:
    - - request: me
        method: GET
        path: /me
    - - request: slow
        method: GET
        path: /slow

Stream steps (WebSocket and SSE) #

A stream is opened by a websocket or sse step, named like a request: others refer to it as $live, which is the handshake (assert: status of: $live equals: 101 works). send writes a message (WebSocket only), receive waits for the next message on the stream that matches a small where, and close ends it; a stream left open is closed when the run (or a load iteration) ends. A received message is a response: $order has the message text as its body, and its stream fields are read like headers (event and id on SSE, type on WebSocket). The block below lists the steps one after another, as they would sit in a pipeline.

- websocket: live                # opens a WebSocket; others refer to it as $live (the handshake)
  path: /live                    # after the pipeline's host: https is wss, http is ws (or a whole ws(s):// URL)
  query: { room: orders }
  headers: { x-client: ultraman }
  auth: { bearer: "{{token}}" }  # on the upgrade request (default: the pipeline's)
  protocols: [v2.json]           # Sec-WebSocket-Protocol, in order of preference; a token, or a template that renders to one
                                 # ({{secrets.x}} allowed, asked and redacted like a header: some proxies log subprotocols, so prefer
                                 # an Authorization header when the server accepts one)
  options: { timeout: 10000, maxMessage: 1048576, ping: 15000 }   # ms, bytes, ms (0 = never ping)

- send: live                     # one message on $live (WebSocket only)
  json: { subscribe: orders }    # or text: hello, or file: ultraman/files/frame.bin (binary)

- receive: order                 # the next message on $live that matches `where`; becomes $order
  from: $live
  where: { path: $.type, equals: order.created }   # optional: any message without it
  timeout: 5000                  # ms to wait (default: options.timeout)

- extract: order_id              # a received message is a response: extract and assert as usual
  from: $order
  path: $.id

- assert: equals
  of: $order
  path: $.status
  equals: new

- close: live                    # optional: code 1000; the run closes what's left open
  code: 1000
  reason: done

- sse: prices                    # opens a Server-Sent Events stream (GET, accept: text/event-stream)
  path: /prices
  headers: { last-event-id: "{{last_id}}" }   # resuming is yours, not automatic
  options: { timeout: 10000, maxEvent: 65536, maxSize: 52428800 }

- receive: tick
  from: $prices
  where: { event: price }        # SSE: by event name; `path` + `equals`, `contains` and `matches` read the data
  timeout: 3000

where is at most one of { path, equals }, { path, exists: true }, { contains } and { matches }, plus event (SSE only, alone or with one of the others). Messages that arrive and don't match are passed over and counted, never looked at again: a receive is the next match from where the last one left off. A failed receive shows the last three it passed over. repeat: 10 around a receive collects ten messages; a parallel with a receive in one branch and a send in the other is "wait for the push while I act".

stream optionondefaultmeans
timeoutboth30000the handshake, and a receive's default wait; 0 waits with no limit
maxMessagewebsocket1048576one message, in bytes; a bigger one ends the stream
pingwebsocket15000a ping after this many ms of quiet; 0 never pings
maxEventsse65536one line or one event's data, in bytes
maxSizesse52428800 (5 MB in a load)the whole stream; past it the stream ends with a note
idleboth0 (none)ms without any frame or line before the stream is dropped

plainHttp (needed for ws: outside localhost) and ca apply to the handshake as to any request.

GraphQL subscriptions #

A websocket with graphql: speaks graphql-transport-ws: Ultraman sets the subprotocol (no protocols with it), sends connection_init and waits for the ack, and its frames are Ultraman's (no send on it, no receive from it). subscribe starts a subscription (its own $name); receive from it takes the next event whose payload matches, and an event with errors fails it unless allowErrors: true. close on a subscription completes it; on the socket, it completes every subscription and closes. GraphQL over SSE (graphql-sse) isn't supported yet.

- websocket: gql
  path: /graphql
  graphql:
    init: { authorization: "Bearer {{secrets.token}}" }   # the connection_init payload (optional)
    ackTimeout: 5000             # ms to wait for connection_ack (default: options.timeout)

- subscribe: orders              # a subscription on $gql; others refer to it as $orders
  on: $gql
  graphql:
    query: |                     # sent as written; values go in variables
      subscription Orders($min: Float) { orderCreated(min: $min) { id total } }
    variables: { min: 10 }
    allowErrors: true            # optional: an event with errors passes

- receive: order                 # the next event of $orders; its body is the payload ({ data, errors? })
  from: $orders
  where: { path: $.data.orderCreated.id, exists: true }
  timeout: 5000

- close: orders                  # complete for this subscription

- close: gql                     # completes what's left and closes the socket

Checks (assert) #

Every assert has of: $step. Besides that it reads a path of the JSON body, a response header, or neither (the whole body); the "reads" column says what each check allows. The expected value goes in the key of the "compares with" column, and only that one: equals: for status and equals, value: for the rest. The other key is an error.

checkcompares withreadspasses when
statusequals:nothing (a path is accepted and ignored; a header is an error)the HTTP status is it
equalsequals:a path or a header, or the whole bodythe value is the one given
notEqualsvalue:a path or a header, or the whole bodythe value isn't the one given
containsvalue:a path or a header, or the whole bodythe value is it or contains it; without either, the body's text contains it
lessThan, greaterThanvalue:a path or a header, or nonethe number is below (above) it; with none, the duration in ms
exists, notExistsno value (one is an error)exactly one of path or headerthe path finds a value or the header is there (or isn't)
matchesvalue:a path or a header, or the whole bodythe text matches a regex (/^ord_/i with flags i, m, s, u)
typevalue:a path (a header is an error)string, number, boolean, object, array or null
schemavalue:a path (a header is an error)a JSON Schema inline or a .json file in the project

A path and a header together are an error, except where the table says exactly one is needed.

Functions inside {{ }} #

random.uuid, random.email, random.int, random.int(1, 100), random.string(16), random.name, random.phone, random.pick('a', 'b'), now.iso, now.ms, now.s, counter, counter.vu, hmac.sha256(secrets.key, body), hmac.sha1(…), sha256(x), base64(x), urlencode(x). In a load: {{vu.id}}, {{iteration}}. No nesting, no scripts.

Collections (Requests area) #

ultraman/requests/<collection>/collection.yaml:

name: shop
host: "{{env.api}}"
auth: { bearer: "{{token}}" }     # optional, like a pipeline's
headers: { x-tenant: acme }       # optional
variables: { user: ana }          # starting values for {{user}}
contract: { openapi: files/shop.yaml, mode: warn }   # optional: the OpenAPI spec its answers are checked against (a
                                  # file under files/, a path on the host or a URL); strict fails a run's step
graphql: { schema: files/shop.graphql, subscriptions: /graphql/ws }   # optional: the schema its GraphQL requests use (a file
                                  # under files/) and where its subscriptions open their socket (default: the request's path)

A request, ultraman/requests/<collection>/<folders…>/<id>.yaml (save_request takes this whole file):

request: me                       # its id comes from this name
method: GET
path: /me
auth: { bearer: "{{token}}" }
operation: GET /me                # optional: the OpenAPI operation it came from ({ key: GET /me, id: getMe } with an
                                  # operationId); an import writes it, Update from the spec matches by it
checks:                           # extract / assert about this same request: no from / of
  - assert: status
    equals: 200
    source: openapi               # optional: a check the spec owns (Update from the spec may replace it)
  - extract: user_id
    path: $.id
notes: free text

A stream is a request file whose first key is websocket or sse instead of request (save_request takes it the same way, and send_saved_request and Run collection play it):

websocket: live
path: /live
protocols: [v2.json]
messages:                        # ready to send from the panel (WebSocket only); templates allowed
  - name: subscribe orders
    json: { subscribe: orders }
  - name: ping
    text: ping
listen: 2000                     # how long a collection run (or the agent) listens after sending the messages
checks:                          # about the handshake: status, header
  - assert: status
    equals: 101
notes: free text
sse: prices
path: /prices
listen: 3000
checks:
  - assert: status
    equals: 200

Run as part of a collection, the file is four steps: connect, each saved message as a send, a receive that listens listen ms (a timeout there isn't a failure) and a close. A stream request has no mock.

Environments (ultraman/envs/<id>.yaml, shared; ultraman/local/envs/<id>.yaml, this machine) #

Plain name: value text. A secret goes as a reference (token: "{{secrets.token}}"), never as its value. options: holds the same request options as a pipeline.

Load tests (ultraman/load-tests/<id>.yaml) #

name: checkout peak
description: optional             # text
before: { block: seed, with: { n: 10 } }    # once per test (after: the same, at the end)
scenarios:
  - pipeline: checkout            # the pipeline's name
    weight: 3                     # with shared top-level stages, users are split by weight
    from: 0                       # users at the start
    stages:                       # users: go to N over a time; or rate: N iterations per second (open model)
      - { users: 50, for: 1m, name: ramp }
      - { users: 50, for: 5m }
      - { users: 0, for: 30s }
    maxUsers: 200                 # rate stages: the pool's cap
    iterations: 10                # per user (users stages only)
    thinkTime: { min: 1s, max: 3s }   # or a single duration
    pacing: 5s                    # an iteration takes at least this
    cookies: true                 # a jar per virtual user
    setup: { block: login, with: { user: ana } }   # once per user
    data: { file: ultraman/local/data/users.csv, as: data, each: user, onEnd: recycle, order: sequence }
    inputs: { region: eu }
    responses: auto               # auto | discard | keep (bodies kept under load)
    maxSize: 5242880              # bytes of one response kept under load
thresholds:                       # the run fails (exit 1) past these
  p95: 500ms
  errors: 1%
  steps: { login: { p95: 200ms } }
  warn: { p95: 300ms }            # warnings, not failures
apdex: { satisfied: 300ms, tolerating: 1200ms }   # or apdex: true

Limits: a test has at most 10 scenarios and 50 stages per scenario; users is 0 to 1000, rate 0 to 1000 iterations per second, iterations 1 to 1,000,000; no scenario lasts over 3600 s (1 h); and at no second may the planned users add up to over 1000. Stages are all users or all rate in a scenario, and a rate scenario takes no iterations. A stage needs for and one of users or rate. Secrets are never written in inputs.

Exit codes of ultraman run --load: 0 every threshold held and the verdict is holds, queues or limited; 1 a threshold failed, the API rejected or broke, too few requests went out, or the run was stopped; 2 the test never started (a file that doesn't parse, a missing pipeline, input or secret).

Thresholds: p50, p95, p99, max, errors, failedIterations, minRps, apdex (0 to 1), maxWait, streamErrors (a percentage of the connections tried: streams the server closed mid-run, failed handshakes and dropped messages), steps (per step name: p50, p95, p99, max, errors; a receive or a websocket/sse step by its name) and warn (the same, as warnings).
