Who makes it

Ultraman is made by one independent developer. Questions and bug reports go to the project's issues. A security problem goes privately, through GitHub's private reporting, as the security policy says.

How releases are signed

  • The install commands check a signature. Each release publishes a list of checksums (SHA256SUMS) and a signature of that list made with Ultraman's release key. The install scripts for macOS, Linux and Windows carry the key's public half and install only files that match a list with a valid signature; otherwise they stop and change nothing. The key's fingerprint is in Getting started and in the repository's security policy, to compare one copy with the other.
  • Updates from the window are signed. The window installs an update only if it is signed with Ultraman's update key, whose public half is built into the app.
  • The installers are not signed with an Apple or Microsoft certificate. On Windows they are unsigned; on macOS they are signed only ad hoc, not notarized. An installer downloaded in a browser makes your system warn the first time you open it (When your system warns); the install commands don't trigger that warning.

Security reviews

Ultraman's security reviews are internal; no outside party has audited it. What they found so far, as counts by severity and by round, is in Security history.

Third-party notices

Ultraman includes open-source software, each part under its own license: the npm packages of the CLI and the window, the Rust crates of the desktop shell, the bundled Node.js and the fonts. The full list with every license text is in third-party-notices.txt, generated from what each release ships.
